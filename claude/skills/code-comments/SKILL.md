# コードコメントの規約

コメントは次の読み手のためのもので、書き手のメモ帳ではない。
役割分担: コードは HOW、テストは WHAT、コミットログは WHY、コメントは **WHY NOT と制約**。

## 書いてよいもの

コードから読み取れないことだけを書く。

- **制約・不変条件**: コードが示せない前提(「この関数は lock 保持中に呼ぶ」「600 でないと sops が拒否する」)
- **WHY NOT**: 自明に見える別解を採らない理由(「mkDefault では上書きされるためここで固定」)
- **危険の警告**: 触ると壊れる箇所と、壊れ方(「この順序を変えると平文が残る」)
- **外部仕様への参照**: 上流の挙動・バグ・RFC など、コードの外にある根拠

## 書いてはならないもの

- **経緯・作業ログ**: 「以前は〜だった」「〜から変更した」「〜は却下された」。経緯はコミットメッセージへ
- **指示の写し**: ユーザー指示・レビュー指摘・方針文の引用や要約。規約の正本は別にある
- **次の行の言い換え**: コードを読めば分かることの反復
- **自己弁護**: 「これで正しい」「この変更は安全」。レビュアーへの話しかけはコメントではない
- **計測ログの貼り付け**: 判断に使った実測は結論 1 行に圧縮する(「実測で X が必要」)。数値・日付・試行過程の羅列はしない
- **私的メモ・TODO の放置**: やるなら issue か今やる

## 原則

- 周囲のコードのコメント密度・言語・語調に合わせる
- コメントが段落になるなら、設計を単純にするか、doc に置くべき内容かを先に疑う
- 編集で触れた行の古くなったコメント(嘘)は、直すか消す。コードだけ変えてコメントを残さない
- 迷ったら書かない。消しても失われない情報は最初から不要だった
