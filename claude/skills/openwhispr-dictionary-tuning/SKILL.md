# OpenWhispr の聞き間違いを直す

OpenWhispr の文字起こし履歴から繰り返す聞き間違いを拾い、利用者が承認した組だけを登録します。登録の前と後に、本番と同じ条件で整形の結果を測って比べます。対象は Windows の OpenWhispr 1.11 系で、整形にローカル LLM を使う構成です。版が違う場合は、下の「アプリの仕様で知っておくこと」をその版のソースで確かめ直します。

コマンドは Git Bash で、この skill のディレクトリを作業場所として実行する前提で書いています。スクリプトは Node.js 22 以降 (組み込みの `WebSocket` を使う) と Python 3 で動きます。

## 1. アプリを操作できる状態にする

辞書・置換・整形の指示はアプリの中に保存されます。保存ファイルを直接書き換えず、アプリ自身の処理を通して変更します。

1. OpenWhispr を終了し、開発者用の接続口を付けて起動します。Scoop で導入した場合のパスです。GUI アプリなので末尾の `&` で切り離します。

   ```bash
   "$USERPROFILE/scoop/apps/openwhispr/current/OpenWhispr.exe" --remote-debugging-port=9333 --remote-debugging-address=127.0.0.1 >/dev/null 2>&1 &
   ```

   起動して十数秒待ってから、同じ exe を引数なしで `&` 付きでもう一度起動します。起動中のアプリに設定画面が開きます。
2. `node scripts/ow-eval.mjs <file.js>` で、設定画面の中で JavaScript を評価できます。ファイルの中身は async 関数の本体として評価されるので、値は `return` で返します。`await ow.store()` で設定のストア、`await ow.reasoning()` で整形処理を取り出せます。設定はストアの setter で変更します。`localStorage` を直接書き換えると、画面の状態と食い違います。
3. 作業が終わったら「6. 保存して元に戻す」で、接続口なしの通常の起動に戻します。接続口を開いたままにしません。

## 2. 聞き間違いの候補を集める

1. 履歴を書き出します。`--since` は記録時刻 (UTC、`YYYY-MM-DD HH:MM:SS`) で、文字列として比べます。

   ```bash
   python scripts/ow-history.py --since "2026-01-01 00:00:00" --json > history.json
   ```

   各行には Whisper の生の文字 (`raw`) と、整形後に貼り付けた文字 (`text`) があります。アプリは、貼り付け先のアプリ名や、利用者があとで直した文を保存しません。
2. 正しい表記が分かる材料と突き合わせます。
   - 利用者が直してから送った文 (エージェントとの会話記録や投稿) は、記録時刻の近い履歴と並べると、直した跡がそのまま正解になります。
   - 利用者が確認した正解文がある録音は、正解文と機械的に比べます。
3. 正解が無い履歴は、前後の文脈から聞き間違いを推測します。
4. 候補を、聞き間違い・正しい表記・根拠 (利用者の直し、確認済みの正解文、文脈からの推測)・該当する履歴の id の表にして利用者に示します。正しい表記が文脈から 1 つに決まらない語は「保留」として分けて示し、登録しません。候補が無い場合は、無いことと調べた範囲 (期間・件数) を示します。
5. 利用者が承認した組だけを、次の節の分け方で登録先に振り分けます。

## 3. 登録前の結果を測る

登録する前に、今の設定で整形の結果を測って保存します。

```bash
python scripts/ow-history.py --since "2026-01-01 00:00:00" --raw-only > inputs.json
node scripts/ow-cleanup-check.mjs inputs.json pairs.tsv --save before.json
```

`pairs.tsv` は、これから登録する組を「聞き間違い<TAB>正しい表記」で 1 行に 1 組書いたものです。測定の条件は「5. 登録後の結果と比べる」で説明します。

## 4. 登録先を選んで登録する

| 候補の種類 | 辞書 | 整形の指示の聞き間違いの表 |
|---|---|---|
| 英字の名前・専門用語 (カタカナで書かれた製品名など) | 正しい綴りを登録する | 繰り返す聞き間違いを登録する |
| 専門寄りの言葉が別の語になる聞き間違い (同音の別の言葉、存在しない語) | 正しい語を登録してよい | 聞き間違いを登録する |
| 普通の語どうしの取り違え (どちらの表記も文として成り立つ) | 登録しない | 登録しない |

- 辞書: ストアの `updateCustomDictionary({add: [...], remove: [...]})` で変更し、`window.electronAPI.getDictionary()` で結果を確かめます。`window.electronAPI.applyDictionaryChanges` はデータベースだけを書き換え、再起動するまで整形と Whisper のヒントに反映されません。
- 整形の指示: [整形の指示のひな形](references/cleanup-prompt.md) の表に組を足し、ストアの `setCustomPrompt("cleanup", 指示)` で設定します。整形を使うには `setUseCleanupModel(true)` で有効にし、整形のモデルをローカルのものにします。
- 口調を貼り付け先に合わせる設定 (`toneStyleEnabled`) は無効にします (`setToneStyleEnabled(false)`)。有効だと「話し手の言い回しを保つ指示より口調を優先する」文が整形の指示に足され、句読点・用語以外の文字も変わります。
- 置換 (ストアの `setSnippets([...{trigger, replacement}])`) は聞き間違いの直しには使いません。理由は「アプリの仕様で知っておくこと」にあります。置換は、住所やメールアドレスのような、その語だけを単独で言う定型を入れるためのものです。

## 5. 登録後の結果と比べる

登録後に同じ入力で測り、登録前の結果と比べます。

```bash
node scripts/ow-cleanup-check.mjs inputs.json pairs.tsv --save after.json
```

- このスクリプトは、本番の音声入力と同じ設定で整形を呼びます (温度 0、出力が途中で切れたら失敗、思考の抑制と推論量は設定画面の値)。温度を渡さずに `processText` を呼ぶと、既定の 0.7 で動き、本番と違う結果になります。
- 整形の失敗・空の出力が 1 件でもあれば、その測定は比べません。本番では失敗すると生の文が貼られるので、スクリプトも生の文として数えます。アプリで音声入力をしていないときに測り直します。
- 「聞き間違いの残り」が減り、「表の直し・句読点以外で文字が変わった」件数が増えていなければ採用します。この件数は、入力と出力の両方に表の直しを当ててから比べるので、聞き間違いが残った文は「残り」だけに数えます。この件数には、辞書による正しい直し (表に無いカタカナが英字になるなど) も入るので、増えたときは変わった文の中身を見て判断します。
- 表の組が 1 回も出てこない入力では、聞き間違いの残りでは比べられません。その場合は「変わった」件数で、表や辞書が関係ない語を書き換えていないかを確かめます。既存の組が原因で関係ない語が書き換わっていたら (音の近い別の語を辞書の綴りに直すなど)、その文と原因の組を利用者に示し、組の削除や修正を提案します。どうするかは利用者が決めます。
- 候補を拾った履歴で測ると、結果は良く出ます。表の組がその履歴から作られているためです。新しい履歴がたまったら、それで測り直します。

## 6. 保存して元に戻す

1. 設定画面で `window.electronAPI.relaunchApp()` を呼びます。アプリが正常に終了するときに、設定がディスクへ書き込まれます。強制終了すると、直前の変更が失われることがあります。再起動したアプリは接続口を引き継ぎます。この呼び出しで接続が切れるので、`ow-eval.mjs` は「接続が切れました」と表示して終わります。設定画面が開かなければ、exe を引数なしでもう一度起動します。
2. 再起動したアプリの中で、ストアの値と `getDictionary()`・`getSnippets()` を読み、変更が残っていることを確かめます。保存ファイルは圧縮されることがあるので、ファイルを直接読むだけでは判断しません。
3. OpenWhispr を終了し、接続口なしで `&` 付きで起動し直します。`curl -s -m 2 http://127.0.0.1:9333/json/list` が接続できないことを確かめます。

## アプリの仕様で知っておくこと

OpenWhispr 1.11.0 のソース (`resources/app.asar`) で確かめた内容です。

- 置換は、語の前後が文頭・文末・空白・記号のときだけ当たります (`utils/snippets.ts` の正規表現)。日本語の文の途中の語は置き換わりません。置換は整形の後の最終の文にかかります (`hooks/useAudioRecording.js`)。
- 辞書の語と置換の言葉は、どちらも Whisper へのヒントと、整形の指示の後ろに付く辞書の一覧に入ります (`utils/snippets.ts` の `getDictionaryHintTiers`)。聞き間違いを置換に入れると、聞き間違いの表記が「正しい綴り」として渡ります。辞書の一覧の見出しは UI の言語で変わります。
- 整形の指示の後ろには、言語の注意書き (カタカナの外来語は話したとおりに残す) も付きます (`config/languageRegistry.json`)。整形で直したい語は、聞き間違いの表に明示します。
- 本番の整形の温度は 0 に固定されています (`helpers/audioManager.js` の `cleanupTemperature`)。設定画面からは変えられません。
- 日本語指定の Whisper は、英字の名前をカタカナで書くことがあり、辞書のヒントでは英字に変わりませんでした (55 本の録音での実測)。英字への直しは整形に任せます。
- 修正からの自動学習は、貼り付けた入力欄を 30 秒だけ読み (`helpers/ipcHandlers.js` の `startMonitoring`)、空白で区切った語の単位で比べます (`utils/correctionLearner.js`)。日本語では文のかたまりが辞書に入るので、辞書に長い文が無いかを確かめ、あれば利用者の承認を得て消します。
- 名前の呼びかけでアシスタントに回す判定は、Whisper の生の文字で行います (`config/agentDetection.ts`)。カタカナで書かれた名前は英字の名前と一致しません。アシスタント用の操作で呼んだ場合は、この判定を通りません。
