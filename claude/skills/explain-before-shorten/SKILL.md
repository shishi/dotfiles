# 説明を組み立ててから短くする

説明の意味を明らかにしてから、読者に必要な内容を簡潔にします。口頭で伝えるつもりで考えますが、完成文の文体は依頼に合わせます。

## 適用と引き継ぎ

- 文章作成 skill が定めた読者・目的・形式・公開範囲を引き継ぎ、その草稿を推敲します。引用や逐語訳、識別子は書き換えません。
- 依頼と草稿、その前後を読みます。表・図・注記に条件がある場合は、それらも確認します。意味が決まらなければ周辺資料を調べ、それでも必要な情報が足りない場合だけ質問します。
- 技術的な事実は一次資料や実物で確かめます。確認できない条件や挙動を推測で補わず、事実・推奨・可能性を区別します。
- 相談では書き換え案を示し、編集依頼では指定された正本へ反映します。構成の大幅な変更が必要なら依頼範囲と照合し、無関係な文書・設定へ広げません。

## 推敲の流れ

1. 読者に何を理解してほしいかを定めます。概念の説明なら、不要な行動指示や採用判断を加えません。
2. 長さを気にせず説明を組み立てます。何がどう動き、なぜそうなり、どの条件で成り立つのかを具体的にします。抽象語や唐突な否定だけで説明を済ませません。比較や誤解の訂正が目的なら、その対比は残します。
3. 仕組み・条件・例外など別々の話を分け、その場所で必要な内容を選びます。条件は対応する文や表の項目に添え、重要な制約を注記だけに追いやりません。
4. 重複や回りくどい言い方を削ります。主体・動作・因果・比較対象・適用条件と正式な用語を残し、必要な用語は初出で説明します。文脈で明らかな主語は省略できます。独自の略語や短い標語へ置き換えません。
5. 完成文だけを続けて読み、元の長い説明なしで理解できるか確かめます。意味が欠けたら言葉を戻し、伝わらなければ説明の構成へ戻ります。指定の長さで条件を保てなければ、必要な長さや構成を示します。
6. 編集した正本を読み直し、本文・表・図・注記の意味と既存変更の保持を確認します。スライドなど配置が意味に関わる成果物は、対応ツールで改行・重なりも確認します。

通常は完成文、または反映した結果を先に示します。長い下書きや検討過程は並べず、意味・構成を変えた点だけ必要に応じて説明します。保存・表示の未確認部分は確認済みとしません。

推敲後は呼び出し元の最終確認・レビュー・保存や投稿の手順へ戻ります。この skill から文章作成 skill を呼び直さず、投稿や commit の承認範囲も広げません。
