# Windows スクリプトの実行経路を調べる

同じ入力がどのプロセス・シェル・権限・ファイルシステムを通るか確認し、破損する境界を特定します。
調査の依頼だけでレジストリ、UAC、sandbox、スタートアップの設定を変更しません。

## 症状に応じて読む

- パス、バックスラッシュ、改行、日本語、WSL の書込み先がおかしい場合は
  [シェルと文字コード](references/shell-boundaries.md) を読みます。
- 登録が消えた、変更したのに UI が変わらない、プロセス情報が空になる場合は
  [実状態の観測](references/state-observation.md) を読みます。

## 調べて確認する

1. OS、実シェル、PowerShell の版、native Windows/WSL、親プロセス、実行アカウントと
   昇格状態を取得します。ツール名が Bash でも実体を決めつけません。
2. 元の入力と期待する出力を保ち、対象ファイルの実パス、引数、bytes、終了コードを
   境界ごとに照合します。秘密を含む環境変数やコマンドライン全体は出力しません。
3. 観測の不一致は、同じ入力で起動元など一条件を変えて対比します。
   取得失敗、正常な空集合、対象の不在を分けます。
4. 原因に対応する境界だけを修正します。パス変換停止や CR 除去を全子プロセスへ
   広げず、変更した環境変数の伝播先も確認します。
5. 元の起動元と実アプリから同じ操作を繰り返し、保存先と最終状態を取得します。
   同じ仮想ビューから二度読むだけで、外側への反映確認にしません。

CLI 不足の解決は `missing-tools`、winget/Scoop の導入・更新は
`windows-package-maintenance`、GPU の採取は `windows-gpu-diagnostics` を使います。
調査結果には再現条件、原因を区別した観測、修正後の実結果と未確認部分を残します。
