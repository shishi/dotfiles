# ルールを実行に結び付ける

依頼されたルールは、失敗を防ぐ時点と検証方法から配置を選び、実際の実行に結び付けます。記憶保存、同意、今後の宣言だけで完了にしません。

## 行動の修正を求められたとき

行動の修正要求は、すべて望まれた行動との差を示す入力として扱います。
「ルールを直して」「覚えて」という追加依頼を待たず、次の手順を進めます。
疑問形や短い指摘も、元の依頼と実際の行動に照らして意味を判断します。
通常の新規依頼、引用、ユーザー自身の訂正と混同せず、固定語句の検知にはしません。

1. **差と是正を具体化します。** 元の依頼・実際の行動・求められた修正を照合します。
   元の成果物や返答を直し、要求された結果を確認します。以下の恒久対策も同じターンで進め、
   規則や記憶の更新を元の依頼の是正の代わりにしません。
2. **既存の規則と適用経路を調べます。** 共通指示・関連 skill・hook・記憶の本文と、
   実際の読込・呼出・判断を照合します。既存にあれば「既に書いてある」で終えず、
   なぜ適用されなかったかを調べます。未読、入口や適用条件の不足、規則間の矛盾、
   実行時の判断や環境の問題を証拠で切り分け、未取得の原因を断定しません。
   過去の内因を復元できなくても、観測された行動と既存規則が食い違う判断点を特定し、
   その判断点で規則を使うための入力・手順・検証を既存箇所へ結び付けて改善します。
   原因が未確定であることだけを「反映不要」の根拠にせず、再現と対策後の実行で仮説を確かめます。
3. **原因を担う箇所を改善します。** 既存規則の本文・入口・適用手順や処理のうち、
   原因に対応する既存箇所を直します。強い言葉や同じ禁止の追記だけで済ませません。
   規則がなければ、下の配置判断で方法を選び、実装します。
   記憶に置く個人方針・知識は [capturing-memory](../capturing-memory/SKILL.md) で統合します。
   規則と保存手順は記憶に複製しません。
4. **反映と結果を確かめます。** 通常の読込経路で対策が届き、修正要求のあった条件で
   行動と結果が変わること、既存保証を保つことを下の検証手順で確認します。
   Git 管理外の作業メモに、望まれた行動との差、適用されなかった原因と根拠、反映先と変更、
   検証結果を短く残します。反映しないと判断した内容にも理由を残します。
   この記録はユーザー向けの返答へ転記しません。返答自体への訂正には、訂正後の答えを返します。

毎回行うのは反映の検討と、必要な改善・検証です。その場限りの条件は恒久化しません。
ただし、その指摘から再利用できる判断・適用経路の欠陥が分かれば、原因を担う箇所を直します。
新しい規則や記憶が不要でも、元の依頼の是正と確認は省きません。
改善が必要なのに実施・検証できない場合は、未解決のまま「不要」や「完了」としません。
エージェントの行動を制御する指示・skill・hook の正本は、この是正の関連対象です。
元の作業 repo が別でも正本を特定し、そこへ反映します。作業 repo への複製で代替しません。
編集・反映時は共通指示の作業場所・独立レビュー・稼働設定の保全に従います。
この手順はエージェント自身の行動を直す範囲に適用し、無関係な repo の改変、外部への投稿、
認証・権限・変更禁止の境界を広げません。必要な承認や実行不能な範囲は共通指示に従います。

## 依頼と配置

- 元の依頼と訂正から、禁止する判断・行動、求める結果、適用範囲、維持する保証を定めます。
  例に登場した単語だけを禁止せず、文脈上の意図を外した判断を対象にします。
- 規則の追加前に、共通ルール・hook・skill のどれが目的の判断や操作へ最も直接結び付くかを比較します。常時の判断基準は共通ルール、作業固有の手順は skill、必要な時点の注入や機械的に判定できる操作の制御は hook とし、機構があることだけを採用理由にしません。
- リポジトリの指示ファイルを作成・変更する前に、エージェントの実行版・設定、対象と祖先の既存指示ファイル、公式の読込仕様を確認します。
  既存の読込経路で必要な規則が届く場合は、その経路を使います。
  Claude Code が対象の `AGENTS.md` を直接読む環境では、読込のためだけの `CLAUDE.md`・import・symlink・hook を追加しません。
  直接読めない環境では、既存の読込経路の不足を確認してから、必要な入口だけを補います。
- hook を使う場合は現在の本文、登録イベント、配備先と symlink、共通指示との関係を読みます。
  応答の判断は既存の入力時 hook、危険操作の拒否は既存の実行前ガードを優先して統合します。
  作業別の詳細手順は skill に置き、hook から必要なときに参照させます。
- この構成では、応答規則は `~/.agent-shared/hooks/wording-policy.sh`、作業規則は
  `~/.agent-shared/hooks/task-policy.sh` が入力ごとの入口です。
  Claude Code と Codex の両方に同じ共有 hook を登録しているため、既存登録を再利用します。

## 実装と検証

- ルールを作業前に渡します。回答の事後採点・再出力や、失敗後の命令再注入にしません。
  モデルによる意味の判断を、ユーザー入力や回答の固定文字列の一致・不一致で代替しません。
- 既存の同じ規則を置換・統合し、同じ詳細を記憶や複数の hook に複製しません。
  共通指示との矛盾があれば、現在のユーザー指示と上位の権限制約に合わせて解消します。
  vendor cache は変更せず、正本と有効な配布先を更新します。
- 採用した配置の通常の読込・呼出経路で規則が必要な時点に渡ることを確認します。hook を使う場合は登録されたコマンドで実行し、対象の規則が応答前に渡ることを確認します。
  両エージェントの登録と実際の参照先、既存 hook の契約、関連する既存テストも確認します。
  新しい hook の登録や定義変更で trust の更新が必要なら、通常の承認経路で扱います。
- 元の失敗例と維持条件を使い、規則に沿う判断と結果を確認します。
  hook の出力確認とモデルの応答確認を区別し、未確認の挙動を確認済みとしません。
  応答の抑止を依頼された場合は、通常の入力経路で元の失敗が抑止された実回答を確認するまで未完了です。
  誤った前提の訂正や、明示的に求められた別案の説明など、維持すべき応答も確認します。
  失敗した試行を残し、検証した hook の版と実際の注入を照合します。
  配備成功や独立レビューの指摘なしを、抑止できた証拠の代わりにしません。
  必要な独立レビューと commit は共通指示に従います。
- skill・共通指示・再利用するプロンプトを新規作成する場合や、実行者の判断・手順・出力を変える指示の改訂では、
  [empirical-prompt-tuning](../empirical-prompt-tuning/SKILL.md) で実行・修正・再評価を行います。
  上の通常経路の確認と同じ評価として組み込み、全ルール変更へ一律に実験を追加しません。

ルールの作成・変更を明示的に依頼された場合の完了報告には、選んだ配置とその理由、反映したルール、確認した利用経路、未確認事項を記します。
行動の訂正への最終回答は、訂正後の答え・成果物から始めます。規則・記憶を実際に変更した場合は、その末尾に変更した正本と検証結果を示す一文を添えます。
分析・作業経緯は転記せず、本人の判断や操作に必要な未達は明示します。
将来の応答をすべて保証したという表現で、実装・検証結果を置き換えません。
