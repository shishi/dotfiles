# 人間向け文章の執筆規約

## 概要

読者が一度で読める文を書く。このファイルは執筆者(shishi)の規約で、モデルの一般的な好みより優先する。共通原則と文書種別ごとの方針は日本語・英語の両方に適用する。表記規約は日本語固有。

## 共通原則(全言語)

- 対象読者とユーザー指定から文書の主言語を決める。見出し、定型欄、ラベル、本文を
  その言語に統一する。標準テンプレートの初期表記は、言語を混在させる理由にしない
- 一文一義。長くなったら分割する(日本語は 80 字が目安)
- 主語と述語を近づける。二通りに読める文は書き直す
- システムの動作説明は能動態で書く(「保存されます」→「保存します」)
- 結論・要点を先に書き、補足・例外は後に置く
- 仕様にない挙動を推測で補わない。不明点は不明と書くか確認する

## 対象読者と書いてよい情報(全言語)

- 文書はエージェントの作業メモではない。読者のための成果物として書き、作業ログ・
  自分向けの備忘・経緯の羅列を本文に入れない
- 文書ごとに対象読者を定めてから書き始め、文書の冒頭(または PR 説明などの
  メタ情報)で対象読者を宣言する。読者を特定できないなら書かない
- 個人名は、特に必要がある場合または指示された場合に限り、「誰の名前をどこに
  書くか」を先に宣言してから書く
- 厳密な個人情報(氏名・連絡先・credential)に限らず、機微な情報(所属・評価・
  健康・私的な事情・社外秘の事実)もユーザーの許可なく書かない。迷ったら
  書かずに確認する
- これらに反する記述を既存文書に見つけたら、放置せず修正または削除する。
  公開 repo では最優先で対処する

## 文書種別ごとの方針(全言語)

- **意思決定文書**: WHY(なぜ選んだか)と WHY NOT(なぜ他案を退けたか)を書く。現在形の要件と事実で書き、「本改訂では」のような経緯は書かない(経緯は commit log へ)
- **コミットメッセージ**: git-commit skill に従う(WHY 重視の body)
- **エラーメッセージ**: 原因と次の行動を 1 文ずつ

## 日本語の表記規約

| 項目 | 規約 |
|---|---|
| カタカナ語の末尾長音 | 付ける(サーバー、ユーザー、コンピューター) |
| 送り仮名 | 「行う」(「行なう」は不可) |
| 和文と半角英数の間 | 半角スペースを入れる(例: S3 バケットに 3 回) |
| 数字・英字 | 半角。全角英数は使わない |
| 文体 | 地の文は です・ます。箇条書きは体言止め可。一つの文書内で混在させない |
| 読点 | 一文に読点が 3 つ以上付いたら文を分ける |

## 日本語の冗長表現の置換

| 冗長 | 簡潔 |
|---|---|
| することができます | できます |
| 〜という形になっています | 〜です |
| 〜を行う | 動詞にする(リトライを行う → リトライする) |
| 〜においては / 〜につきましては | 〜では |
| 〜というもの | (削除) |
| 注意が必要です | 何をすべきかを具体的に書く |

## チェック

- 日本語: 見出し、定型欄、ラベル、本文に英語だけの文章や不要な英単語が残っていないか確認する。製品名、識別子、コマンド、引用は維持する
- 日本語: 表記ゆれを grep で確認する(長音なしの「ユーザ」「サーバ」、「行なう」)。音読して詰まる文は書き直す
- 独立レビューを依頼する場合は、主言語の統一を明示的な確認項目に含める
- 英語: 共通原則に加えて、不要語を削る(omit needless words)
