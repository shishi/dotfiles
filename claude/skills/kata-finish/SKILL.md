# 工程 7: 統合・保全・後片付け

[kata](../kata/SKILL.md) の工程 7 を進める手順です。次へ進む条件は kata の工程表にあります。

## 手順

1. 統合する版で、工程 6 の検証が済んでいることを確かめます。同じセッションの前の版で通っていても、統合する版で取った証拠でなければ工程 6 へ戻ります。
2. 作業場所と分岐元を確かめます。通常の checkout か、worktree か、ブランチの無い detached HEAD かで、取れる終え方と片付けが変わります。worktree のパス (`git rev-parse --show-toplevel`) は、後で本体へ移動してから消すために、移動前に控えます。detached HEAD ではローカルで統合せず、`git push origin HEAD:refs/heads/<新しいブランチ>` で push するか、残します。分岐元は計画・会話・ブランチの upstream から決め、「たぶん main」と推測で統合先を決めません。決まらなければ確かめます。
3. 終え方を決めます。依頼・承認・repo の指示で決まっていればそれに従い、決まっていなければ下の 3 つから利用者に選んでもらいます。作業が終わったように見えても、統合するかは利用者が決めることなので、決まっていない終え方を先回りして実行しません。作業を破棄するのは利用者が明示的に求めた場合だけで、選択肢には出しません。破棄するときは、消えるブランチ・commit の一覧・worktree の場所を示し、破棄してよいという明示の返答を得てから消します。「片付けておいて」のような曖昧な返事は破棄の確認とみなしません。

   | 終え方 | すること | 作業場所 |
   |---|---|---|
   | ローカルで統合する | 分岐元へ統合し、統合後の版で検証する | 統合後の検証が通ってから片付ける |
   | push して PR を作る | `git push -u origin <ブランチ>` で push し、forge の CLI などで、repo の PR テンプレートと規約に沿って分岐元宛ての PR を作る | レビュー対応のために残す |
   | そのまま残す | 何もしない。場所とブランチ名を報告する | 残す |

4. merge・pull・rebase・cherry-pick は [git-lossless-integrate](../git-lossless-integrate/SKILL.md) で実行します。未コミットの変更と稼働中の設定を守り、競合を解消してから反映します。
5. 統合した場合は、統合後の版で関連する検証を実行します。失敗したら、たまたまの失敗と決めつけず、ブランチと作業場所を残したまま原因を調べます。ローカルの統合は push 前なら戻せるため、片付けより調査を先にします。
6. 反映先の実物を確かめます。push したなら remote の commit、PR を作ったならその URL と本文を取得して照合し、URL を報告します。
7. 後片付けは、ローカルで統合して統合後の検証が通った場合と、破棄を確認した場合だけ行います。worktree は、その中ではなく本体の checkout へ移動してから、手順 2 で控えたパスを `git worktree remove` で消し、`git worktree prune` で古い登録を整理します。専用ツールで作った場所は、その終了ツールで片付けます。worktree を消した後に、統合済みのブランチを `git branch -d` で消します。`-d` は未統合のブランチを消さないため、`-D` は破棄を確認した場合だけに使います。
8. 片付けの対象は、工程 2 の記録で自分が作ったと示せる場所だけです。作業の開始時から入っていた worktree や detached HEAD、古そうに見える他の worktree は残します。作成主体・使用状況・未統合の成果を確かめ、ディレクトリ名だけで所有者を決めません。整理は [git-lossless-integrate](../git-lossless-integrate/SKILL.md) の手順に従います。
9. `git worktree remove` が未コミット・未追跡のファイルを理由に拒否したら、`--force` を自分の判断で付けません。`git -C <worktree> status --porcelain -uall` で一覧を取り、ファイルごとに内容と作成元を確かめます。自分が作った一時ファイルや、内容を既に別の場所へ保全したものは、承認範囲内で整理します。成果物で保全先が依頼・計画から決まるものは、そこへ commit するか移します。他のどこにも無い成果で扱いを依頼・計画から決められないものだけ、一覧を示して、commit する・本体の checkout へ移す・削除する、のどれにするかを利用者に選んでもらいます。すべて処理してから worktree を消します。

## 注意

- push・PR 作成・破壊的な操作は、共通指示の承認範囲を広げずに行います。push が拒否されたら remote の変化を調べ、force push は明示の指示がある場合だけにします。
- 他のセッションや利用者が使っている作業場所は片付けません。
