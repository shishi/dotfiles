# kata の入口

調査・操作を伴う作業では、依頼文と既知の文脈から暫定のタスクリストを利用者へ先に出し、その後に求められる結果、許可された操作範囲、守る既存条件、成功を確かめる方法を、依頼と既にある情報から判断します。既知の事項を作り直さず、確認するのは次の判断や実行を変える不足だけです。

## 直接進められるかを判断する

依頼全体の操作と影響範囲が明確で、完了までに重要な未決事項がなければ、必要な操作を実行して結果を確かめます。工程を省く許可、別の設計・計画、専用の記録、不要な委譲を追加しません。変更を伴わない依頼を変更作業へ広げません。

直接進める場合も、変更前の状態と他者変更を確かめ、完了を述べる前に [kata-verify](../kata-verify/SKILL.md) で依頼と実物を照合します。追跡対象を変えた場合は、変更後の diff/status も確認します。不具合・失敗・想定外の結果が出たら、[investigation-discipline](../investigation-discipline/SKILL.md) で原因と必要な次の操作を判断します。これらは詳細工程へ移るかどうかにかかわらない開始・完了の条件です。

不明な点があれば、その点を判定する資料・skill・観測だけを追加します。作業名、文の短さ、変更行数では手順を決めません。小さく見える操作でも、重要な前提・権限・既存保証が未確認なら、その確認を先に行います。

目的・方式を決める判断や、複数の依存関係を計画する必要が生じたときに、[詳細工程と通過条件](references/workflow.md)から該当する工程へ進みます。直接進められるかを判断するためだけに、全工程の本文を先読みしません。

## 共通して守ること

- 読むのは現在の判断・操作に必要な手順です。同じ版の既読本文と、対象・前提が変わらない証拠を再利用します。必要になった工程の skill は、その工程へ入る時点で読みます。
- 操作前の安全・権限・承認境界、作業場所と他者変更の保全、適用される受入・独立レビュー、完了前の証拠確認は既存の指示に従います。直接進める判断でこれらを無効にしません。
- 結果を得たら依頼と実物を照合して終えます。途中で重要な不足や失敗が分かったら、その原因と影響に必要な工程へ移り、関係のない工程まで一括で増やしません。

詳細工程を使う場合の設計・計画・進捗・作業メモ・レビュー・commit・統合は、上の参照先に従います。
