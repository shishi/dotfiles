# マイク入力を経路ごとに調べる

物理入力、加工済み入力、対象アプリの録音を同じ発話条件で比べ、劣化する段を特定します。機種固有の配線設定と実機の調整値は関連記憶・設定の正本から取得します。

## 測定

- 録音・再生の内容とタイミングを利用者へ予告します。通話アプリの確認録音は送信せず、確認後に削除します。
- codec、入力デバイス、channel mapping、物理 gain/boost、OS の入力、対象アプリが実際に選んだ入力を確認します。デバイス名だけで同じ経路と扱いません。
- 左右を別々に、無音と同じ距離・声量の発話で測ります。声量、無音ノイズ、clipping、声の欠け、遅延を比較します。別機種の左右選択や音量値をコピーしません。

## 調整と受入

1. 物理 gain/boost を変える場合は、声とノイズの両方を再測定します。音量が上がっただけでは改善としません。
2. 必要なときだけノイズ抑制を追加し、原音と加工後を比較します。小さい声の欠けや遅延も確認します。ノイズが再現しない機種へ同じ処理を標準装備しません。
3. OS では良好でも特定アプリで悪化するなら、アプリの入力選択、形式変換、自動 gain、抑制設定を調べます。加工後のノイズまで再増幅されるか、同じ録音経路で比較します。
4. アプリごとに必要な処理が違うと確認できた場合は、既存 graph の別入力への分離を検討します。混合原音の追加や処理の重複で声・ノイズ・遅延がどう変わるかを測って選びます。
5. 採用設定を環境の正本へ反映し、通常のアプリ入口から録音と再生を再確認します。OS のメーターだけで通話経路の受入を完了しません。

PipeWire では [Filter-Chain](https://pipewire.pages.freedesktop.org/pipewire/page_module_filter_chain.html) が入力と出力の stream を持ちます。実行版の graph、channel、接続先を確認して構成し、特定機種の pin 設定を一般化しません。
