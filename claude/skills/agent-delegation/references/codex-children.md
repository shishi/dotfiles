# Codex の子エージェントとモデル選択

常用の司令塔は `gpt-6.1-sol` / `high` または `gpt-6-astra` / `high` とし、要件整理・分割・採否・統合を担います。
独立した担当範囲と受入条件を切り出せ、引き継ぎ・検証の負担に見合う作業は、
ユーザーから毎回指示を受けなくても子エージェントへ委譲します。
短いコマンドの実行・結果の確認は、親が直接処理することを第一候補にします。

役割は仕事内容で選び、モデルと推論量は今回の作業の曖昧さ・影響範囲・検証の容易さで選びます。
`default` や「レビュー」という名前だけでモデルを決めません。次の表は初期値であり、
同じ役割でも仕事内容に応じて選び直します。Astra の子も通常の選択肢とします。

| 仕事内容・目的 | モデル | 推論量の初期値 |
|---|---|---|
| 対象と判定方法が明確な検索・抽出・集計、変更規則が決まった局所的な修正 | `gpt-6-luna` | `high` |
| 要件と担当範囲が明確な実装・テスト・文書作成、複数箇所の関係を追う調査 | `gpt-6.1-sol` | `medium`。複雑な因果関係を追う場合は `high` |
| 曖昧な要件、相反する制約、広い影響を伴う設計・実装・原因調査 | `gpt-6-astra` | `high` |
| 設計・正しさ・仕様とスコープの独立レビュー | `gpt-6-astra` | `high`。狭い機械的な照合に限り `gpt-6.1-sol` / `high` も選べる |
| 特定モデルに与える指示や挙動の検証 | 検証対象のモデル | 検証対象の推論量 |

- 既存の `explorer`・`worker`・`default` と専門役を使い、起動ごとに `model` と `reasoning_effort` を明示します。上位指示と利用可能なモデル・推論量の制約を守ります。役割ファイルで固定されたモデル・推論量は起動引数より優先されるため、その役割の固定値を確認して選びます。
- `config.toml` の子の既定値は指定漏れ時の Sol / medium であり、選択手順の代わりにしません。モデル別に同じ役割を複製せず、柔軟に選ぶ役割ファイルにはモデル・推論量を固定しません。
- モデルを選ぶ子は履歴全体を継承せずに起動します。`fork_turns` がある場合は `"none"`、`fork_context` がある場合は `false` を使います。目的、対象ファイル、必要な要件と既存保証、根拠、検証方法を渡します。
- 書き込み担当と対象を明示し、同じファイルの並行編集を避けます。他者の変更を戻さないよう伝えます。子から成果・直接の検証結果・未解決点を受け取り、親が採否と統合を判断します。
- 独立レビューの起動条件・観点・入力・通過条件は `review-gate` に従います。モデル選択を理由に省略・代替しません。gitleaks 実行やハッシュ集計だけなら、レビューという名称であっても親の直接実行か Luna を選びます。
- 大量の文書を読む場合も、件数だけで Astra にしません。機械的な抽出は Luna、関係の整理は Sol、曖昧な規則や矛盾の判断は Astra を候補にします。Astra 自身の挙動を検証する作業は検証対象を変えません。
- 子の作業で曖昧な仕様や未解決の因果関係が判明したら、親が担当とモデルを再判断します。必要なら取得済みの根拠を渡して上位モデルの子を新しく起動し、同じ失敗を繰り返しません。
