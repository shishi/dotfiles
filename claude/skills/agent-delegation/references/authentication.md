# CLI の認証方式と送信先の確認

- 起動前に認証方式・provider と接続先上書きの有無を確認します。Codex を委譲・レビュー役として起動するとき (端末多重化ツールから対話で起動する場合を含む) は `-c 'openai_base_url=""'` を渡し、出力ゲートの中継を通さず公式の接続先へ送ります。承認要求には、この事前承認、対象 repo と担当範囲、入力ファイル、CLI が追加取得する指示・関連記憶・ファイル・コマンド出力の範囲、送信先の確認結果、秘密情報検査結果を示します。認証情報そのものは出力しません。接続先や範囲が変わった場合は承認範囲と照合し直します。
- Claude は `claude auth status --json` の `loggedIn`・`authMethod`・`apiProvider` と、環境変数・読み込む settings の `env` にある `ANTHROPIC_BASE_URL`・`CLAUDE_CODE_USE_BEDROCK`・`CLAUDE_CODE_USE_VERTEX`・`CLAUDE_CODE_USE_FOUNDRY` を確認します。Codex は `codex login status` の結果から認証方式だけを抽出し、app-server の `config/read` で `model_provider`・選択された `model_providers` の `base_url`、組み込みの provider の接続先を変える `openai_base_url` (空なら公式の接続先)、環境変数の `OPENAI_BASE_URL` を確認します。確認用の app-server には、実際に使う起動行のうち設定を変える引数 (`-c 'openai_base_url=""'` などの `-c`・`--config`) を同じ値で渡し、その実効値で判定します。app-server は `--profile` を受け付けないため、profile を使う起動では、その profile の設定ファイル (`$CODEX_HOME/<名前>.config.toml`。`CODEX_HOME` の既定は `~/.codex`) にある `model_provider`・`model_providers`・`openai_base_url` も、葉のキーごと (`model_providers.<id>.base_url` など) に `-c` で渡します。起動行の `-c` と同じキーは渡しません。起動行に `-c` が無ければ中継の接続先が見え、確認を通りません。profile・CLI 引数による上書きも含む実効値を使い、認証方式と接続先ホストだけを報告します。API キーを含み得るログイン状態の生出力、アカウント情報全体、環境変数全体を出力しません。
