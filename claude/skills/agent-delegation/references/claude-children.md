# Claude Code の委譲とモデル選択

常用の司令塔は `fable` です。ユーザーが `opus` を選んだ回はその選択を維持します。
短いコマンド・結果照合は親が直接処理することを第一候補にします。
独立した担当範囲と受入条件を切り出せ、引き継ぎ・検証の負担に見合う作業を委譲します。

## 委譲先の選択

最上位の Claude は、Claude 内の子と `codex-delegate` を、[作業の割当・観測・利用枠と履歴](execution.md)と同じ基準で選びます。explore(所在探索・原因調査・読解)、chore(定型修正・テスト追加)、implement(feature / bugfix)という種別だけで Codex を優先しません。必要なツール・権限、既存文脈、引継ぎと統合の負担、同種作業の実績、レビュー余力から担当を決めます。共通 AGENTS.md と同参照の循環禁止に従い、受託側の Claude は Codex へ再委譲しません。

- `codex-delegate` の対象外: 設計判断とユーザーとの対話が要る作業、レビュー(review-gate / codex-review skill の責務)、記憶 repo への書き込み。`~/.codex` が dotfiles の `codex/` を指していないマシンでは chore と implement を委譲しません。
- タスクごとの選択: ネットワークを開けるか(既定は遮断)、`workspace-write` を今の worktree に流してよいか(codex の上書きは差分に現れないため、未コミット変更と範囲が重なるなら先に commit します)。
- 委譲で入った変更は自分が書いた変更と同じ扱いです。委譲専用の検査は持たず、差分確認と`review-gate` による独立レビューで見ます。
- Codex へは定型作業なら `gpt-6-luna` / `high`、通常の実装・調査なら `gpt-6.1-sol` / `medium`(複雑なら `high`)、広い影響を伴う難しい作業なら `gpt-6-astra` / `high` を初期値にし、CLI のモデルと推論量を明示します。Codex の子の既定値は、委譲先の CLI 本体のモデルを変えません。

## Claude 内の子の選択

役割とモデルは別々に選びます。次の表は初期値であり、件数や役割名だけでなく、
今回の作業の曖昧さ・影響範囲・検証の容易さで選び直します。

| 仕事内容・目的 | モデル | 推論量の初期値 |
|---|---|---|
| 限定検索・抽出・集計、変更規則が決まった局所的な変換 | `haiku` | `low`〜`medium`(対応モデルのみ) |
| 要件が明確な通常実装・テスト・文書作成・調査 | `sonnet` | `medium` |
| 複雑だが範囲が絞れた原因調査・実装 | `opus` | `medium`。必要なら `high` |
| 曖昧な設計・広い影響・矛盾の判断 | `fable` | `high`。親が Opus の回は Opus を基本とし、Fable の子が必要なら明示選択 |
| 独立レビュー | `opus`(親が Fable でも同じ) | `high`。狭い機械的照合のみ `sonnet` / `high` も選べる |
| 特定モデルの挙動検証 | 検証対象のモデル | 検証対象の推論量 |

- 既存の組み込み役・専門役を使います。通常の Agent 起動で `model` と、対応する `effort` を選びます。別モデルを選ぶときは全履歴を継承する `fork` を使わず、目的・対象・要件と既存保証・根拠・検証方法を渡します。
- 起動時の `model` は定義ファイルの `model` より優先します。未指定時の `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` は選択手順の代わりにしません。組み込み `Explore`・`Plan` にも起動時のモデルを指定します。これらの既定動作は子の環境変数だけでは変わりません。
- モデルの優先順位は Claude Code 2.1.251 以降、起動ごとの `effort` は 2.1.292 以降を前提とします。実行版とモデルが対応する値を使います。一律上書きの `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` と `CLAUDE_CODE_EFFORT_LEVEL` はこの使い分けには設定しません。
- レビュー3役は `model: opus` / `effort: high` を既定にします。Opus がモデル単位で利用不能なら起動時に `fable` へ上書きします(狭い機械的照合は上表の `sonnet` も可)。既存専門役の `model: opus` も起動時に上書きできます。モデル別に同じ役割を複製しません。
- 担当範囲を明示し、他者の変更を戻させず、同じファイルの並行編集を避けます。子の成果・検証結果・未解決点を親が照合し、必要なら担当モデルを選び直します。gitleaks 実行やハッシュ集計だけを高性能レビュー役へ渡しません。
- 独立レビューの観点・起動条件・エンジン選択は `review-gate` を維持します。Codex へ送るレビューは Astra / high、Claude 側は上表に従います。モデル選択を理由にレビューを省略しません。
