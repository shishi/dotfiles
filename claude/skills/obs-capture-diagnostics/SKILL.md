# OBS のキャプチャ診断

入力信号、キャプチャソース、キャンバス、表示・録画先の設定を分けて照合します。
使う機器・用途・個人の既定値は関連記憶から取得し、別の機器へ固定値をコピーしません。
GPU プロセスと VRAM の採取が必要なら `windows-gpu-diagnostics` を使います。

## 色と HDR

1. 目的がプレビュー、録画、配信のどれかを確認します。
   配信や録画に必要な音声・出力互換性を、プレビュー用途の設定で落としません。
2. 入力機器の実出力、カードと driver が提示する形式、OBS のソース設定を確認します。
   ピクセル形式、bit 深度、色空間、range を一組として照合します。
   HDR キャプチャでは対応する 10-bit 形式が必要です。P010 が選べることだけで HDR としません。
3. 白浮き・過剰彩度は、入力とソースの色空間/range の不一致を先に調べます。
   カード側の彩度・コントラストで不一致を隠しません。
4. ソースが一致してから、キャンバスの HDR/SDR 変換、白レベル、表示先を調整します。
   モニターの仕様値と調整済みの実測値を区別します。

## 遅延と同期

- 入力 FPS、取得 FPS、キャンバス FPS、表示の refresh rate を確認します。
  それぞれの対応形式を調べ、同じ値にできることを前提にしません。
- キャプチャの buffering を比較します。無効化で遅延が減るかと、フレーム落ちが増えないかを
  同じ条件で測ります。録画・配信中なら必要な安定性も維持します。
- グローバル音声、ソース内の音声、監視先の経路と同期ログを確認します。
  不要な音声源を候補として一つずつ外し、必要なマイクや配信音声を一括で無効にしません。
- 同じカードを複数のソースや常駐アプリが同時に開いていないか確認します。
  ソースの再利用と別インスタンスを区別し、必要なら占有側を特定します。
- source projector と preview projector は表示対象が違います。
  用途に合う表示を選び、二重描画・拡大縮小・黒帯の有無も確認します。

変更前後で色の同じ場面、映像と音声の同じイベントを比較します。
設定の保存だけでなく、利用する projector / 録画・配信結果と再起動後の保持も確認します。
driver 更新や常駐アプリの停止・削除は、依頼で許可された範囲に限ります。

設定名は [OBS のキャプチャソース](https://obsproject.com/kb/video-capture-sources)、
HDR の前提は [HDR 対応デバイス](https://obsproject.com/kb/video-capture-devices-with-hdr-support)
で確認します。
