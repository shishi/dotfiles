# Web で先例を調べて比べる

1. 依頼の目的と守る条件から、先例で確かめたいことを決めます。公開できる名称や仕様を使い、利用者が達成したいことや解くべき問題は一般化して Web を検索します。
2. 同じ問題を解いた別々の実装や運用を、少なくとも 3 件調べます。広く使われ、成果や運用実績を一次資料でたどれる先例を優先します。公式仕様や実装の本文を開き、設計や内容を把握します。結果は作った組織の運用報告や評価結果などで確かめます。検索結果の抜粋や、同じ仕組みを説明する資料・機能の列挙で件数を埋めません。直接の先例が少なければ、同じ問題を解く隣接分野の事例まで広げます。
3. 本文を開いた各事例について、資料の URL と本文から確認できた点を短く残します。今回の目的と必須条件を各事例に同じように当て、どこが役立つかと、どの条件では合わないかを比べます。複数の事例から取り入れる点と調整・見送りが必要な点を選びます。そこから今回の設計・内容・手順に必要な性質を導きます。公開の先例を十分に取得できない場合は、探した範囲と不足が判断に及ぼす影響を記録します。

対象の現物や公式仕様の調査は、この調査と並行か、その後に進めます。[investigation-discipline](../investigation-discipline/SKILL.md) で両方の結果を照合し、今回の判断に必要な根拠がそろってから、結論・提案・実装へ進みます。同じ目的と条件について確認済みの先例は再利用します。
