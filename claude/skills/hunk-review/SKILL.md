# Hunk でコードや差分を表示する

Hunk の起動から表示位置の操作までをエージェントが行います。対象を表示中のセッションが無ければ、エージェントが端末を起動して Hunk を開きます。同梱手順は、セッションが無いときに利用者へ起動を頼むよう案内しますが、この入口の指定を優先します。利用者に起動を頼むのは、エージェントが端末を起動できる経路が無いと確かめた場合だけです。

表示先の指定がなければ、現在のタブを左右に分割 (vsplit) し、Hunk を右側に表示します。その配置で対象を表示中の Hunk があれば、同じペインを使います。

Herdr App では、まず `herdr-app` で `pane.split` の `right` を使います。この操作が失敗して App を端末から操作できないと分かったら、Core 経由で現在のタブの右端に追加します。そのときは作業端末の `herdr.space` と `herdr.tab` を両方引き継いで Hunk を起動します。

エージェントが Herdr の端末の外 (`HC_TERMINAL_ID` が無い環境) で動いていて、Herdr Core が動いている場合は、herdr-core の手順に従い `hc` で Hunk を起動します。対象の作業場所を開いている端末があれば、`hc get` でその端末の `herdr.space` と `herdr.tab` を読み、Hunk の端末に付けて同じタブに表示します。そうした端末が無ければ、利用者が指定したスペース、指定がなければ `hc ls` に出る既存のスペースから 1 つを選び、その `herdr.space` だけを付けます。`herdr.tab` が無い端末は、Herdr がそのスペースに新しいタブを作って表示します。ラベルの無い端末は Herdr の画面に出ないため、ラベルを付けずに起動して終えません。ラベルを持つ端末が 1 つも無い場合は、起動した端末の名前と `hc attach` での開き方を利用者に伝えます。

ファイルは `hunk open`、作業ツリーの差分は `hunk diff`、コミットは `hunk show` で開きます。パッチファイルには `hunk patch`、GitHub の PR には `hunk gh pr` を使います。

差分を開いたら、説明するファイルや変更箇所に表示位置を合わせます。セッション情報や端末の表示から対象を確認し、どの端末に何を開いたかを利用者に伝えます。

## ライブセッションの操作

実行中の Hunk に同梱された手順を使います。
`hunk skill show hunk-review` を実行し、出力された手順と制約に従います。
Nix store の絶対パスを保存せず、実行するたびにバイナリから取得します。
手順の取得に失敗したら `missing-tools` で実行版と配備を確認します。
別の古いコピーを代わりに読みません。
この入口は実行のたびに Hunk から手順を取得するため、Hunk を更新しても入れ直しは要りません。
Hunk が案内する `npx skills add` は実行しません。同名の skill を導入して、この入口を上書きするためです。

同梱手順の対象はライブセッションの CLI 操作です。
起動済みセッション、対象 repo / worktree、利用できる接続経路を確認してから操作します。
個人環境の版別実測は関連記憶を参照し、現在の版の仕様と照合します。
端末の起動・終了には、その端末の操作手順と承認範囲に従います。
