# Windows フォントの状態と寿命を確認する

ファイル、登録、セッション内のロード、実アプリの描画を別々に確認します。
診断の依頼だけで global 導入、レジストリ削除、アプリ停止、再起動を行いません。

## 導入と可視性

1. 対象フォント、OS、描画 API、user/global、永続化の要件と既存のプロジェクト方針を読みます。
   特定実機での user-scope の失敗を、すべての Windows の禁止へ一般化しません。
2. [登録とロードの照合](references/registration.md) を使い、実ファイルと実ハイブ、
   GDI/DirectWrite の列挙、必要な文字の実描画を対応づけます。
3. 変更を実行する場合は、自分が追加した resource の成功数と元の登録を控えます。
   セッション内通知の成功を、次回ログオン後の永続化と同じ結果にしません。
4. 新しい process と要求された再ログオン/再起動後から確認します。
   OS の設定画面だけで対象アプリの対応まで証明しません。

## 更新と撤去

[ロック・撤去・再起動](references/removal.md) を読み、対象の登録とファイルを先に対応づけます。
解放はファイルが存在する間に行い、第三者の resource 参照を無制限に外しません。
共有違反を権限不足と取り違えず、使用中アプリや他 session の状態を確認します。

再起動削除が必要なら、承認済みの対象だけを OS の API で予約し、他の予約を維持します。
予約成功と実削除成功は分け、再起動後に対象ファイルと登録を再取得します。

実機の変更禁止や既存の試験方針を維持します。スタブ試験、別 VM、実アプリで確認した
範囲を分け、実行できない検証を成功扱いしません。Scoop の manifest/update は
`scoop-manifest` と `windows-package-maintenance`、実ハイブの観測差は
`windows-script-diagnostics` を使います。
