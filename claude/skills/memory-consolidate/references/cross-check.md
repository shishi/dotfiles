# 記憶群の主張を突き合わせる

記憶群全体の重複と矛盾は、主張を一件ずつ取り出し、同じ場面に当てはまる主張どうしを話題ごとに比べて見つけます。ファイルを一つずつ読む方法や語句で検索する方法では、読み手が思い付いた語の範囲しか比べません。そのため、言い回しの違う重複や、別々のファイルにある矛盾を見落とします。ファイルを分担して読むと、各担当は自分のファイルの外を見ません。

比べる相手には、記憶に加えて、記憶と同じ判断を述べうる指示を含めます。AGENTS.md、フックが注入する指示、skill がこれに当たります。

## 1. 主張の一覧を作る

比べる版を先に決めます。記憶は整理の基準 commit の本文を使います。指示は取り出しを始めた時点の本文を使い、その写しを Git 管理外の作業領域に残します。指示の作業ツリーには、ほかのセッションの未コミット変更が含まれることがあり、commit を記録するだけでは取り出した本文を再現できないためです。各ファイルの全文から、意味を独立して確かめられる主張 (事実・方針・手順・適用条件・例外・価値観) を一件ずつ取り出し、JSON Lines に書きます。一行が一件です。

```json
{"file": "<repo からの相対パス>", "id": "<file>#<連番>", "source": "memory|instruction", "subject": "<述べている対象>", "condition": "<OS・版・プロジェクト・場面。無ければ空>", "assertion": "<中身を 1 文で>", "quote": "<原文の引用>"}
```

- `source` は、取り出す側がファイルの場所 (記憶 repo か、指示のファイルか) から付けます。比べる側に判断させると、指示のファイルを記憶として数える取り違えが起きます。
- 見出しや参照だけの文は主張にしません。複数の主張を含む文は分けます。要約するときも、元に無い条件や事実を足しません。
- 取り出しはファイル単位で分担できます。
- 直し終えるまでに、指示のファイルがほかのセッションに書き換えられることがあります。残した写しとの差分で書き換えを見つけます。差分は、比べ始める前と、手順 5 を終えて保存する前に確かめます。引用が今も見つかるかを確かめるだけでは、追加された規則や変わった見出しを見落とします。書き換えられたファイルは、その主張と、その主張を相手に挙げた判定の行を捨てます。捨てた判定の行を根拠にした手順 5 の自分の編集も、ほかのセッションの変更を残したまま先に取り消します。そのうえで、そのファイルについて手順 1 から 4 をやり直します (主張を取り出し、話題に振り分け、新旧どちらかの主張が入っていた話題を比べ直して数えます)。やり直しで出た候補は、手順 5 で確かめて直します。

## 2. 話題に分ける

`subject` の表記は担当ごとにばらつくので、そのままでは同じ対象をまとめられません。話題は対象の名前ではなく、主張が当てはまる場面 (いつ、何を、どうするときか) で作ります。名前の違う対象を挙げていても、同じ判断を述べる主張を同じ話題に入れるためです。一覧の主張を見渡して話題の一覧を作り、各主張を、当てはまる場面の話題すべてに振り分けます。振り分けた後、すべての主張に話題が付いたことを数えて確かめます。

## 3. 話題の中で比べる

話題ごとに、`source` が `memory` の主張の一件ずつを、同じ話題のすべての主張と比べます。指示どうしの組は比べません。比べる単位は (記憶の主張, 話題) の組です。複数の話題に振り分けた主張は、話題ごとに比べます。

相手の一件ずつについて、まず二つの主張が両方とも当てはまる場面があるかを決めます。条件が同じ場合に加え、一方の条件が他方を含む場合 (全体の方針とプロジェクトの記憶など) も、その場面では両方が当てはまります。両方が当てはまる場面が無ければ、その相手とは関係がありません。両方が当てはまる場面があれば、その場面での中身を比べ、次のどちらかに当たる相手を挙げます。

- `duplicate`: 中身が同じ (言い回しが違っても同じ意味なら重複)
- `contradiction`: 両立しない。狭い側が例外として書かれていても、ここでは矛盾として挙げます。例外かどうかは手順 5 で元の根拠から確かめます。

(記憶の主張, 話題) の組ごとに必ず一行を書きます。

```json
{"id": "<記憶の主張の id>", "topic": "<話題>", "pairs": [{"with": "<相手の id>", "verdict": "duplicate|contradiction", "note": "<理由を 1 文>"}], "outside": ["<別の話題>"]}
```

重複も矛盾も無ければ `pairs` を空にします。同じ場面の主張が担当の話題の外にありそうだと気づいたら、その話題を `outside` に挙げます。比べる作業は話題単位で分担できます。分担するときは、各担当に手順 2 の話題の一覧 (話題の名前と当てはまる場面) も渡します。ほかの話題を知らないと、`outside` に挙げる先が分からないためです。

## 4. 判定の行を数え、話題の境界を直す

スクリプトで次を数えます。

- 手順 2 の振り分けのすべての (記憶の主張, 話題) の組に、判定の行がちょうど一つあること
- 判定の行の `id` が `source: memory` の主張であること。`pairs` の `with` がすべて一覧に存在し、`verdict` が二つの値のどちらかであること

欠けた組は比べ直します。この数え上げで確かめられるのは、振り分けたすべての組に判定の行が返ったことまでです。比べる側が相手を一件ずつ見たかは確かめられません。別々の話題に入った主張どうしの組は、比べられていません。`outside` に挙がった話題があれば、その記憶の主張をその話題にも振り分け、その話題を比べ直します。

## 5. 実物で確かめて直す

判定は候補です。比べた側は、条件の違いや記憶の側にしかない事実を見落とすことがあります。直す前に相手の箇所を前後も含めて開き、両方が当てはまる場面で同じ中身か、両立しないかを確かめます。全体の方針と違うプロジェクトの記憶は、本人がそのプロジェクトだけの例外として示したものかを、[assessing-memory](../../assessing-memory/SKILL.md) の手順 1.5 で確かめます。

確かめた重複と矛盾は、[improving-memory](../../improving-memory/SKILL.md) の手順で直します。記憶に残すかどうかは assessing-memory で決めます。利用者が示した価値観・好み・訂正は、指示に同じ規則があっても残します。矛盾で誤っているのが指示の側なら、直す先はその指示の編集先です。その編集が現在の依頼で許可された範囲に無ければ、直さずに報告します。

直す作業を分担するときは、確かめた組でつながる記憶のファイルを同じ担当に渡します。組の両側を別々の担当が直すと、両方が相手の側に残すと決めて、主張がどちらのファイルからも消えることがあるためです。各担当は、渡された組の相手のファイルを、improving-memory の手順 1.3 で全文を読む範囲に含めます。
