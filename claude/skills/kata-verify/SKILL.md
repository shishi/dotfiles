# 完了を主張する前の証拠確認

工程に関係なく、完了・成功・修正済みを述べる前、満足を表明する前、作業を委譲する前、commit・PR・次の task へ進む前に、この手順で証拠をそろえます。[kata](../kata/SKILL.md) の工程 6 では、この確認の後に工程表の 6 行目に従って照合・commit・記録を進めます。決まった言い回しだけでなく、言い換えや成功をほのめかす表現にも同じく適用します。

## 手順

1. 主張ごとに、それを証明する検証を決めます。

   | 主張 | 証拠 | 証拠にならないもの |
   |---|---|---|
   | テストが通る | 今の版で実行したテストの出力 (失敗 0) | 前の実行、「通るはず」 |
   | lint が通る | 今の版で実行した linter の出力 (エラー 0) | 一部のファイルだけの確認、そこからの推測 |
   | ビルドできる | ビルドの終了コード 0 | lint の成功、ログの見た目 |
   | 不具合を直した | 元の症状を再現した手順で、症状が消えたこと | コードを変えたこと |
   | 回帰テストが元の不具合を検出する | 修正を外した版で赤、修正を戻した版で緑 | 一度通ったこと |
   | 委譲した作業が終わった | diff と実物の確認 | 担当の「完了」報告 |
   | 要件を満たした | 計画と元の依頼を読み直して作った要件ごとの照合表 | テストが通ったこと |

2. 検証を、主張する対象の版で、省略せずに実行します。一部だけを走らせた結果で全体を主張しません。出力の全体と終了コードを読み、失敗件数を数えます。
3. 結果が主張を支えるかを判断します。支えない場合は、実際の状態を証拠とともに示し、未達の工程へ戻ります。支える場合も、主張には根拠にした証拠を添えます。

## 注意

- 次の考えが浮かんだら、検証を省こうとしている合図です。主張を止めて手順 1 へ戻ります。

  | 浮かぶ考え | 実際 |
  |---|---|
  | 「もう通るはず」「たぶん直った」 | 推測は証拠になりません。検証を実行します。 |
  | 「自信がある」 | 確信は証拠の代わりになりません。 |
  | 「うまくいった」と先に言いたい | 満足の表明は検証の後にします。 |
  | 「lint が通ったから大丈夫」 | lint はビルドやテストの代わりになりません。 |
  | 「担当が成功と報告した」 | diff と実物で独立に確かめます。 |
  | 「一部を確かめたから十分」 | 一部の確認は、確かめた範囲しか証明しません。 |
  | 「今回だけは省いてよい」「早く終えたい」 | 例外にする理由になりません。 |
