# ルールを hook に反映する

依頼されたルールは hook に実装します。記憶保存、同意、今後の宣言だけで完了にしません。

## 依頼と配置

- 元の依頼と訂正から、禁止する判断・行動、求める結果、適用範囲、維持する保証を定めます。
  例に登場した単語だけを禁止せず、文脈上の意図を外した判断を対象にします。
- 現在の hook 本文、登録イベント、配備先と symlink、共通指示との関係を読みます。
  応答の判断は既存の入力時 hook、危険操作の拒否は既存の実行前ガードを優先して統合します。
  作業別の詳細手順は skill に置き、hook から必要なときに参照させます。
- この構成では、応答規則は `~/.agent-shared/hooks/wording-policy.sh`、作業規則は
  `~/.agent-shared/hooks/task-policy.sh` が入力ごとの入口です。
  Claude Code と Codex の両方に同じ共有 hook を登録しているため、既存登録を再利用します。

## 実装と検証

- ルールを作業前に渡します。回答の事後採点・再出力や、失敗後の命令再注入にしません。
  モデルによる意味の判断を、ユーザー入力や回答の固定文字列の一致・不一致で代替しません。
- 既存の同じ規則を置換・統合し、同じ詳細を記憶や複数の hook に複製しません。
  共通指示との矛盾があれば、現在のユーザー指示と上位の権限制約に合わせて解消します。
  vendor cache は変更せず、正本と有効な配布先を更新します。
- hook を登録されたコマンドで実行し、対象の規則が応答前に渡ることを確認します。
  両エージェントの登録と実際の参照先、既存 hook の契約、関連する既存テストも確認します。
  新しい hook の登録や定義変更で trust の更新が必要なら、通常の承認経路で扱います。
- 元の失敗例と維持条件を使い、規則に沿う判断と結果を確認します。
  hook の出力確認とモデルの応答確認を区別し、未確認の挙動を確認済みとしません。
  必要な独立レビューと commit は共通指示に従います。

完了報告には、反映した hook とルール、確認した利用経路、未確認事項を記します。
将来の応答をすべて保証したという表現で、実装・検証結果を置き換えません。
