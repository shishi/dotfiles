# Spec-scope review(単独発動ラッパー)

仕様・スコープ観点(`~/.claude/agents/spec-scope-reviewer.md`)を 1 レーンだけ走らせる。

## 入力組成(review-gate のレーン1 と同一規則)

1. **タスク記述 — 既存テキストの逐語コピーに限る**: 元のユーザー依頼・訂正を含め、
   参照された plan doc・spec も渡す。実装後に要約・言い換えして渡すことを禁止
   (実装中の合理化がタスク記述へ逆流し、レビューが「合理化への準拠確認」に化けるため)。
   該当テキストが無ければ停止してユーザーに求める(新規に書き起こして代用しない)
2. **レビュー対象**: `git diff HEAD` の全文 + untracked ファイル
   (`git status --short --untracked-files=all` で列挙)の本文
3. **設計 doc**: repo 内 doc(`docs/` 等)の存在を確認し、あれば該当部を含める。
   存在確認をせずにレビューを開始しない
4. AGENTS.md / CLAUDE.md(global + project)の該当規約
5. 差分に現れない成果物の本文・状態と、要件に対応する検証の実行結果。
   会話で渡す調査結果や文書も含む。実装者の自己評価で代用しない

**実装中の判断過程をプロンプトに書かない**。元の依頼・訂正・成果物・検証結果は渡し、
実装者の合理化から隔離する。対象を分割しても全対象・全要件の照合責任は呼び出し側に残る。

## 実行

`spec-scope-reviewer` agent を新規に dispatch し(Claude Code は Task tool、Codex は spawn agent。
Codex 側の agent は `~/.codex/agents/spec-scope-reviewer.toml`)、上記入力をプロンプトで渡す。

## 結果処理(単独発動時)

1. 引用検証: 欠陥主張の引用はレビュー対象と、要件未達の引用は要件ソースと照合。
   不一致は棄却し [spec-scope-n] 付きで記録
2. 採否判定(指摘は採用命令ではない。現在の依頼への実益か回避する具体的リスクを
   説明できるものだけ修正し、他は理由付きで棄却)→ 修正 → 入力を再組成して再 dispatch。
   採用した blocker/should がすべて解消し、全要件が証拠付きで満たされ、
   未確認・判定不能の対象がない場合だけ clean。必要な確認を周回数で打ち切らない
3. 「判断できない」が 1 件でもあれば、不足する元の要件・実物・検証結果を取得して
   再判定する。新たな要件の創作や実装者の自己評価で埋めない
4. 自力で解消できる間は続行する。収束・停止の条件は AGENTS.md に従い、
   停止時は依存しない作業を済ませ、残件・試行結果・再開条件を示す。停止を clean に数えない

## Final report(単独発動時)

```
## Spec-scope レビュー結果
- 反復: <X> 回 / ステータス: ✅ clean | ⚠️ 未完了
- 全要件の判定と根拠 / 未確認・判定不能の対象
- 修正した指摘: [spec-scope-n] と要約 / 棄却: [spec-scope-n] + 理由 / 未対応 note: [spec-scope-n]
```
