# 工程 3: 実行可能な計画にする

[kata](../kata/SKILL.md) の工程 3 を進める手順です。次へ進む条件は kata の工程表にあります。superpowers の対応 skill は手順 0 で読み込みます。superpowers が無い環境でも、以下の手順だけで工程を終えられます。上流とこの手順が食い違う場合は、この手順と共通 AGENTS.md に従います。

## 手順

0. skill 一覧に `superpowers:writing-plans` があれば、手順 1 の前に、Skill ツールがあればそれで開き、無ければ skill 一覧にある SKILL.md を読んで、現在版の本文を取得し、計画の書き方として以下の手順に組み込みます。一覧に無ければ、以下の手順だけで進めます。
1. 工程 1 で決めた目的・方式・維持条件と、工程 2 で確かめた作業場所・基準版を前提にします。
2. 仕事を、単独で検証できる task に分けます。各 task に次を書きます。
   - 成果物と対象ファイル
   - 依存する前の task の出力
   - 検証方法 (実行するコマンド・操作) と合格とみなす結果
3. 全 task で元の全要件を覆っているかを照合します。漏れた要件は task に足すか、満たせない理由を明示します。
4. 実行方式 (司令塔が直接実行するか、子へ task を渡すか) と担当を、共通指示の委譲の規則で選びます。
5. 計画を `Task 1`・`Task 2` のように番号付きの見出しで、実在のファイルに保存します。正式な計画を求められた場合は既存の正式な保存先へ、それ以外は Git 管理外の場所に、この計画専用のディレクトリを作って置きます (両 CLI の sandbox から書ける `/tmp/claude-<uid>/` の下など)。進捗の `progress.md` も同じディレクトリに置くため、別の計画とディレクトリを共有しません。上流の保存先だけを理由に公開文書を増やしません。
6. 実装に入る前に、実装中であることを記録します。

   ```sh
   ~/.agent-shared/bin/kata-active codex start <計画ファイル>
   ```

   記録があるセッションでは、計画を終えないまま止まろうとすると Stop hook が差し戻します。計画を終えたとき、または利用者の指示で中止したときは `~/.agent-shared/bin/kata-active codex done` で記録を消します。記録があっても止まれるのは、全 task を検証の証拠つきで終えたときと、次のときです。

   - 本人の認証・判断・承認が必要で、その理由と最小の操作を具体的に報告するとき
   - 利用可能な別の手段を試しても進めず、試した内容と再開の条件を報告するとき
   - 利用者が一時停止を求めたとき、または質問・説明だけを求めて、それに答えたとき

   これらの場合は記録が残り、利用者の返答の後も計画を続けます。

## 注意

- 上流の計画書の承認待ちや実行方式の選択メニューを、新しい承認条件にしません。本人にしか決められない選択と、依頼・repo の手順が求める承認は維持します。
- 計画は会話だけで済ませず、実行時に読み直せるファイルにします。短く明確な仕事で計画が不要なら、工程 3 を省いた判断と根拠を示して工程 4 へ進みます。
