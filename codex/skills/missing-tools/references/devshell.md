# devShell が供給するツールとプロセス環境

非対話シェルでは direnv の hook が動かず、インストール済みのツールが PATH に現れない場合があります。
まず repo の flake / shell 定義と CI の実行方法を確認し、同じ環境で起動します。

- flake があれば `nix develop -c`、既存手順で必要なら `--impure` を使います。
  `.envrc` を使う環境では、許可済みの `direnv exec .` も利用できます。
- ツールを供給する定義があるのに見つからない場合は、呼出元の shell と PATH 継承を調べます。
  user/global へ同じツールを追加して供給元を二重にしません。
- Language Server Protocol のサーバーは、クライアントが起動する子プロセスです。
  devShell にサーバーを足しただけでは、外で起動済みのエディターやエージェントへ届きません。
  起動元も同じ環境へ入れ、クライアントの通常の入口からサーバーの起動を確かめます。
- WSL を Windows から呼ぶ場合は、対象 distro・作業ディレクトリと実バイナリを確認します。
  Windows 側で入れた同名実行ファイルを Linux の実行結果に混ぜません。

環境定義の修正が必要なら現在の依頼範囲で行い、利用経路で版とコマンドの結果を確認します。
個人環境の global ディレクトリや過去の誤導入は関連記憶から取得します。
