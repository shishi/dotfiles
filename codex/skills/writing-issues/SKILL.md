# Issue の作成と編集

issue は、読者が問題と必要な対応を理解して作業に入るための文書です。公開する内容と置き場は AGENTS.md、文章は writing-prose に従います。

## 問題・対応・完了条件を組み立てる

- **問題**: 冒頭で何が起きるかを示します。再現条件、現在の挙動、必要な挙動の差から、対応する理由が分かるようにします。
- **対応**: 実施する範囲と方針を具体化します。決定済みの内容を候補へ戻しません。調査や判断が依頼内容なら、判断に必要な材料と基準を示します。
- **完了条件**: 必要な挙動や成果を、観測できる条件で示します。項目が複数ある場合はチェックボックスで追跡できます。

見出しの数や順序は issue の規模と既存テンプレートに合わせます。用語定義、原因、実行手順、参考資料は、その issue の理解・実施に必要なものだけ加えます。専門語は読者に必要な範囲で定義し、同じ対象を曖昧な別名で呼び分けません。

原因を説明する場合は、確認した事実と推定を分け、根拠となるコードのパス・記録・資料を示します。採らない案の説明は、対応範囲の誤解を防ぐ場合に含めます。

## 正本の参照と実行手順

- 既存の仕様・SQL・スクリプトが正本なら、実物を開いて参照先と内容を照合します。本文には目的・前提・使う箇所・完了条件を残し、正本へ辿れば実施できるようにします。番号や対応表を記憶だけで書きません。
- SQL やコマンドの全文複製は必須ではありません。issue 自体が実行手順の成果物で、その場で必要な場合に掲載します。複製する場合は正本と適用する版を示し、両者の判定条件を一致させます。
- 詳細な実行手順には、実行環境・前提・期待結果と、結果によって必要になる次の操作を示します。安全に実行できる検証環境で、記載どおりの手順と結果を確認します。
- 破壊的なコマンドを文書検証だけのために実行しません。fixture・一時環境・読み取り確認など、実物の変更を伴わない経路で検証します。代替検証では証明できない実行条件を区別し、実行を伴う確認が必要なら AGENTS.md の権限・本人操作の規則に従います。
- 文書に残す検証環境や日付は、適用条件の判断に必要なものに限ります。実機固有の値は読者が置き換えられる表記にし、私的な作業記録は含めません。

## 投稿前後の照合

元の依頼・根拠資料と全文を比較し、問題、対応、完了条件がつながっているか確認します。レビューは review-gate に従い、投稿・更新前の全文を渡します。投稿後は同じ issue の本文を取得し、送信した本文と照合します。
