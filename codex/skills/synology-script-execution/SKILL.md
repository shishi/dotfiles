# DSM での単発スクリプト実行

到達経路、DSM 版、共有の実パス、実行ユーザー、インストール済みツールは関連記憶と実機で確認します。
SSH が利用できることを前提にせず、この作業のために新しい公開ポートや常駐サービスを増やしません。

1. 実行する変更、対象ファイル、必要権限、結果を回収する共有先を確定します。
   対象共有を操作できても、DSM での実行権限があるとは限りません。
2. スクリプトを承認済みの共有へファイルとして置きます。
   転送元と転送先のハッシュや bytes、改行、実行対象の絶対パスを照合します。
   UI のテキストエリアに長い本文を埋め込んで、引用や改行の変化を隠しません。
3. DSM の「タスク スケジューラ」でユーザー定義のスクリプトを作成します。
   対象ユーザーを選び、定期実行は無効のままにします。
   タスク本文は、確認済みファイルを `sh` などの実在 interpreter で起動する短い呼び出しにします。
4. 必要なコマンド・オプションを対象 NAS で確認します。
   シェルや jq の機能を別環境の版から推測しません。
   JSON の組み立ては利用可能な serializer を使い、credential をタスク本文・出力へ残しません。
5. 手動の一回実行で、開始・終了、終了コード、必要な stdout / stderr を回収します。
   実行ボタンの押下だけで成功とは判断せず、対象の変更結果を読み直します。
6. 取得や通信の失敗では redirect、HTTP status、返却物の内容を確認します。
   `curl` のリダイレクト未追従と通信遮断を区別します。
7. 結果を保全し、作成した一時タスクとファイルだけを片づけます。
   継続利用するものは、承認された保存先・実行頻度へ反映します。

スケジュール・実行ユーザー・通知の項目は、対象 DSM 版のタスク スケジューラのヘルプで確認します。
