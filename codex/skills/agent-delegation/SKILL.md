# エージェントへの作業割当

共通 AGENTS.md の事前送信承認・権限境界・司令塔の責任を引き継ぎます。担当選択と起動前の確認を行い、成果と直接の検証結果を回収します。短い操作は親が直接処理することを第一候補にします。

## 起動前に読む参照

現在の担当と実行方式に対応する本文を、起動前に読みます。同版を既読なら再利用し、不要な方式の参照は読みません。

| 場面 | 必須の参照 |
|---|---|
| 委譲・レビュー・受入・長いバックグラウンド実行の割当、観測、待機直前の判断 | [作業の割当・観測・利用枠と履歴](references/execution.md) |
| Codex 内の子を起動 | [Codex の子とモデル選択](references/codex-children.md) |
| Claude 内の子、または最上位の Claude から Codex への委譲を選択 | [Claude Code の委譲とモデル選択](references/claude-children.md) |
| 別 CLI を一般作業・レビュー・対話で起動 | [認証方式と送信先の確認](references/authentication.md) |
| モデルが利用不能、または代替候補を決める | [モデル代替](references/model-fallback.md) |

役割だけでモデルを固定せず、担当する仕事の曖昧さ・影響範囲・検証の容易さから選びます。別 CLI で受託中の場合は、同じツール内の子にも受託範囲と別 CLI への再委譲禁止を引き継ぎます。

## T3 Code で動いているとき

T3 Code では、会話から起動した子 (同じ provider の native の子と `delegate_task` の子) はその会話と親子として記録され、親から状態と結果を確かめられます。利用者の依頼を受けた司令塔は、独立した担当範囲と受入条件を切り出せ、引継ぎと検証の負担に見合う仕事 (独立した実装・調査・レビュー、長いバックグラウンド作業、並行できる作業) を、利用者に頼まれるのを待たずに子として起動し、この親子関係で管理します。受託側の子は、担当タスクで明示された場合だけ子を起動します。起動手段は T3 の指示に従い、別 provider への委譲とレビューも `delegate_task` で起動します。`codex-delegate` などの CLI 用の adapter で起動した子は T3 の子として記録されないため、T3 の外で動いているときに使います。

利用者が「スレッドを立てて」「別スレッドで」と頼んだ場合も、今の会話の仕事の続きや一部なら子として起動します。親を持たない最上位のスレッド (`t3_thread_launch`) は親子関係が付かず、この会話から辿れなくなるため、利用者が独立したスレッドとして扱うことを明示した場合だけ使います。そのスレッドの作業が完了条件まで終わり、結果を回収したら、`t3_thread_organize` で settle して Working の一覧から外します。短い操作を親が直接処理する基準は変えません。

T3 の Working の一覧に並ぶのは親を持たないスレッドだけで、子は表示されません。最上位のスレッドを増やすと、一覧のどれが親か分からなくなります。子は、親の返答で見失わないようにします。子を起動した返答と、子が動いている間の返答では、末尾に子の一覧 (リンク・担当・状態) を添えます。状態は、起動時の応答と T3 から届いた通知で更新し、動いている子に状態の問い合わせを繰り返しません。子の結果を伝える返答には、その子のリンク・担当・結果を載せ、次の返答から一覧を外します。

## 実行用 skill へ渡す

- T3 Code の外では、Codex から Claude への一般作業は `claude-delegate`、Claude から Codex へは `codex-delegate` を使います。T3 Code の中では上の「T3 Code で動いているとき」に従います。この skill は各 adapter のコマンド・権限設定を複製しません。
- 独立レビューは `review-gate` と `claude-review` / `codex-review` へ渡します。レビューの編成・順序・採否は `review-gate` を正本とし、受託側で追加の独立レビューを重ねません。
- 起動前に担当範囲・入力・維持条件・受入条件・権限・締切・進捗の観測点を確定します。CLI の接続先確認と秘密情報検査を終えてから、既存の承認範囲に合う実行へ進みます。
- 受託側から成果物・直接の検証結果・未解決点を受け取り、司令塔が実物と照合して採否・統合を判断します。完了通知だけでは作業完了としません。
