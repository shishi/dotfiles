# 工程 7: 統合・保全・後片付け

[git-commit](../git-commit/SKILL.md) の最後、または [kata の工程 7](../kata/references/workflow.md#開始から終了まで) から進む手順です。

## 手順

1. 成果を残して終えるときは、反映する版の検証と最後の commit が済んでいることを確かめます。計画がある場合は工程 6 の記録も済ませます。途中の commit で作業が残っている場合は、作業メモを保持して残りの作業を続けます。
2. 作業場所と現在のブランチを確かめます。worktree のパス (`git rev-parse --show-toplevel`) は、本体へ移動してから消すために、移動前に控えます。detached HEAD ではローカルで統合せず、`git push origin HEAD:refs/heads/<新しいブランチ>` で push するか、残します。統合や PR の対象となる分岐元は計画・会話・ブランチの upstream から確認します。 分岐元を確定できなければ、統合や PR の作成前に利用者に確認します。
3. 終え方は依頼・承認・repo の指示に従います。既定ブランチへ直接 commit して完了する運用なら、手順 6 に進みます。作業ブランチの扱いが決まっていなければ、統合・PR・そのまま残すの中から利用者に選んでもらいます。作業を破棄するのは利用者が明示的に求めた場合だけです。消えるブランチ・commit の一覧・worktree の場所を示し、破棄してよいという明示の返答を得てから消します。「片付けておいて」のような曖昧な返事は破棄の確認とみなしません。

   | 終え方 | すること | 作業場所 |
   |---|---|---|
   | 既定ブランチへの commit で完了する | 既定ブランチの履歴に今回の commit があることを確かめ、`git show` で内容を照合する | checkout を使い続ける |
   | ローカルで統合する | 分岐元へ統合し、統合後の版で検証する | 手順 7〜10 に従う |
   | push して PR を作る | `git push -u origin <ブランチ>` で push し、forge の CLI などで、repo の PR テンプレートと規約に沿って分岐元宛ての PR を作る | レビュー対応のために残す |
   | そのまま残す | 何もしない。場所とブランチ名を報告する | 残す |

4. merge・pull・rebase・cherry-pick は [git-lossless-integrate](../git-lossless-integrate/SKILL.md) で実行します。未コミットの変更と稼働中の設定を守り、競合を解消してから反映します。
5. 統合した場合は、統合後の版で関連する検証を実行します。失敗したら、たまたまの失敗と決めつけず、ブランチと作業場所を残したまま原因を調べます。ローカルの統合は push 前なら戻せるため、片付けより調査を先にします。
6. 反映先の実物を確かめます。push したなら remote の commit、PR を作ったならその URL と本文を取得して照合し、URL を報告します。成果を残す場合は後片付けの前に、完了後に必要な情報を PR または commit からたどれることを [作業メモの置き場](../kata/references/workflow.md#作業メモの置き場) の方針に沿って確かめます。
7. 手順 6 の確認が済んだら、[kata の報告手順](../kata/SKILL.md#タスクリストで指示と報告事項を追う) に従って利用者に先に報告し、確認や追加修正に使う worktree・ブランチ・作業メモ・検証資料を保持します。保持した作業場所と片付けを再開する条件を報告します。後の入力で利用者の確認が済み、追加修正の予定がないと分かったら、手順 8 以降を再開します。未完了の仕事、PR のレビュー対応が続く仕事、「そのまま残す」を選んだ仕事、利用者が保存を指定した仕事の作業メモも保持します。ほかのセッションのメモも保持します。
8. 手順 7 で保持する理由がなくなり、実行記録への追記を終えたら、役目を終えた作業メモを削除します。[作業メモの置き場](../kata/references/workflow.md#作業メモの置き場) で今回自分が作って控えたパスを使います。控えたパスが実パスと一致し、作業場所の `docs/kata/` 直下にあることを確認します。Git の除外対象で、今回の不要なメモだけが入っていて、追跡ファイルがなければ、確認した絶対パスを `memo_dir` に入れます。`rm -r -- "$memo_dir"` でそのディレクトリだけを削除し、パスがなくなったことを確かめます。
9. 作業場所を片付けるのは、手順 7 の報告を済ませて保持の条件がなくなり、ローカルで統合して統合後の検証が通った場合です。利用者が破棄を明示的に承認した場合は、その指示に従います。工程 2 の記録で自分が作ったと示せる場所だけを対象にし、使用状況と未統合の成果を確かめます。Git の除外対象も worktree と一緒に消えます。worktree を消す前に、自分の作業メモのうち保存対象のものを本体の checkout の作業メモ置き場へ移し、移した内容を確かめます。ほかのセッションのメモなど、保持すべきファイルが中に残る worktree は保持します。
10. worktree とブランチの片付けは [git-lossless-integrate](../git-lossless-integrate/SKILL.md) に従います。本体の checkout へ移ってから、手順 2 で控えた worktree を `git worktree remove` で消します。専用ツールで作った場所はその終了ツールを使います。未コミット・未追跡のファイルを理由に拒否されたら、同 skill の「worktree の削除が拒否されたとき」に従います。worktree を消した後に `git worktree prune` で古い登録を整理し、統合済みのブランチを `git branch -d` で消します。`-D` は破棄を確認した場合だけに使います。

## 注意

- push・PR 作成・破壊的な操作は、共通指示の承認範囲を広げずに行います。push が拒否されたら remote の変化を調べ、force push は明示の指示がある場合だけにします。
- 他のセッションや利用者が使っている作業場所は片付けません。
