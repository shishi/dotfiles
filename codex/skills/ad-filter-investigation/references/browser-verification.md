# 広告表示をブラウザーで検証する

DNS の応答、配信物の用途、画面に残る広告を対応づけるための手順です。DNS 検査の成功だけで広告除去を完了にしません。

## 比較する条件を揃える

1. 広告除去機能のない検証用プロファイルを用意し、拡張機能の一覧を確認します。Brave Shields やコンテンツブロッカーが広告を消した結果は、DNS フィルタの検証に使えません。シークレットモードも第三者 Cookie などの条件が変わります。
2. OS の DNS と、ブラウザー独自のセキュア DNS・VPN・プロキシの実際の設定を確認します。設定表示と、対象通信がその経路を通った証拠は分けます。変更は検証用プロファイルに限定し、変更前の値を記録します。
3. 同じ記事、表示サイズ、操作、Cookie 条件で比較します。広告の読み込みを待ち、スクロール、記事遷移、全面表示・固定フッターの発火操作を再現します。設定版、観測時刻、キャッシュ状態、待機時間と結果を残します。
4. 比較が必要なら、検証用プロファイルで通常の DNS、比較用 DNS、通常の DNS への復元を順に確認します。広告の入札、時刻、キャッシュも変わるため、1 回の差だけで DNS が原因と断定しません。可能なら同時刻の通信と対応づけます。

Chrome のモバイルエミュレーションは表示幅や User-Agent の確認に使えます。実機 iOS、Android、アプリ内ブラウザーの操作と通信経路を確認したことにはなりません。

## 広告と通常コンテンツを観察する

- 広告の位置・形式・素材 URL と、本文・画像・動画の表示を記録します。広告枠が空欄でも、本文まで欠落した場合は成功にしません。
- DevTools で表示中の要素と参照先を確認し、ページ内広告と、サイト自身の案内・販促バナーを区別します。同一ホストの画像を DNS で一括遮断すると記事も失う場合は、利用可能な URL・コンテンツ制御で扱います。
- CAPTCHA、証明書エラー、アクセス拒否、未読込の画面は広告非表示の証拠にしません。ブラウザーや操作ツールの安全制約に従い、拒否されたページへ別経路でアクセスしません。
- スクリーンショットは比較条件と対応づけて保存します。Chrome DevTools のコマンドメニューにある `Capture screenshot` は表示領域、`Capture full size screenshot` はページ全体の記録に使えます。実際に残った広告も証拠に含めます。

## 判定と終了

結果は「確認した環境・操作」「消えた広告と残った広告」「通常機能」「未確認」に分けます。比較側でも広告が出ない場合や通信経路が未確認の場合は、因果の比較を未判定にします。

終了時は検証用の DNS 設定を戻し、自分で作ったタブ・ウィンドウ・不要な一時プロファイルを片付けます。既存の利用者プロファイルは変更しません。利用者が検証終了を指定したら、確認済みの証拠と残件をまとめ、新しい調査へ広げません。
