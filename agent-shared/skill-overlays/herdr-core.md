## このリポジトリでの補足

この節より後ろは、インストールされている hc が `hc --skill` で出力する手引きです。手引きの次の記述は、この節の書き方に置き換えて読みます。

- 手引きは `blocked` を「人が必要なので利用者に聞く」としています。この repo では、子が `blocked` を報告したら画面を読んで質問と権限確認を見分けます。委任した作業の範囲内の質問は、選択肢を確かめて `hc keys` で答えます。権限確認は対象の操作を照合し、不足する承認を利用者から取得します。
- 手引きの例はモデルを版番号で指定しています。Codex のモデルは、起動のたびに `"$HOME/.agent-shared/bin/codex-model" <系統>` で最新の名前を解決して渡します。
- 手引きは「エージェントは常に interactive で起動し、one-shot の print mode を使わない」としています。この規則は、途中で画面を見たり指示を送ったりする子だけに使います。ほかの skill の手順が `claude -p`・`codex exec` で起動すると定めている委譲・レビュー・試行 (codex-review、codex-delegate など) は、その手順どおりに起動します。
- 手引きの「Slow commands」の節は、自分のシェルの道具がコマンドの終了まで待たされる前提で書かれています。Claude Code の Bash の `run_in_background` と Codex のコマンド実行のセッションは、この前提に当たりません。遅い処理を hc で動かすかは、この skill の description の条件 (継続観測や途中のやり取りが要るか) で決めます。
