## このリポジトリでの補足

この節より後ろは、インストールされている hc が `hc --skill` で出力する手引きです。手引きの次の記述は、この節の書き方に置き換えて読みます。

- 手引きは `blocked` を「人が必要なので利用者に聞く」としています。この repo では、子が `blocked` を報告したら画面を読んで質問と権限確認を見分けます。委任した作業の範囲内の質問は、選択肢を確かめて `hc keys` で答えます。権限確認は対象の操作を照合し、不足する承認を利用者から取得します。
- 手引きの例はモデルを版番号で指定しています。Codex のモデルは、起動のたびに `"$HOME/.agent-shared/bin/codex-model" <系統>` で最新の名前を解決して渡します。
- 手引きの対話起動は、途中で画面を見たり指示を送ったりする子に使います。対話版の Codex は `--no-daemon` を指定します。委譲・レビューの adapter や試行が `claude -p`・`codex exec` を指定している場合は、その CLI 呼び出しを Core の子端末で実行します。
- 委譲を受ける CLI には、対話・非対話を問わず、起動するプロセスの環境に `AGENT_DELEGATED_SESSION=1` を渡します。親のシェルだけで設定しても Core の子には届きません。対話起動では、たとえば `hc run --bg --name "$job_name" --cwd "$job_cwd" -- env AGENT_DELEGATED_SESSION=1 codex --no-daemon` のようにします。モデル・権限は実際の担当に合わせて指定し、初回の依頼は子の準備ができてから `hc send` で渡します。
- `HC_TERMINAL_ID` がある場合は `hc get "$HC_TERMINAL_ID"` で親を確かめます。名前と作業場所を指定して `--bg` で起動し、返された端末アドレスと、親がある場合はそのアドレスを照合します。対話作業は初回依頼が届いたことを確認します。起動時に渡せない場合は、子の準備ができたことを画面で確かめてから `hc send` を使います。依頼には委譲元・担当範囲・権限・再委譲の境界・結果の返し方を書きます。
- 短いローカル操作は親が実行します。長いコマンドや検証は、途中の観測や中断に備える必要があれば Core で起動します。

### 非対話の委譲・レビューを子端末で実行する

親が adapter の入力を準備し、秘密情報検査を終えてから、CLI 呼び出しと入出力の処理を一時スクリプトに置きます。同じ作業ディレクトリとモデル・権限・入出力の設定で起動し、必要な変数とファイルの絶対パスはスクリプト内か引数で渡します。

Core のプロセスは親のシェルと環境が異なるため、実行する環境で認証・接続先・sandbox・hook・deny を照合します。Core からの起動でも、本来の CLI に必要な承認を省かず、実行する CLI・引数・書込先を示して通常の承認経路を使います。承認やガードを保てない操作は Core に移しません。

```sh
hc run --json --bg --name "$job_name" --cwd "$job_cwd" -- bash "$job_script"
```

一時スクリプトは adapter が定めた `AGENT_DELEGATED_SESSION=1` と入出力を使い、CLI と出力保存の成否を終了コードで返します。親は端末アドレスを控え、`hc wait` と `hc get` で状態を確かめます。待ちが打ち切られたら同じアドレスを使います。子が動いている間はイベントやログを読み、終了後は子の終了コードと成果物を adapter の結果確認に渡します。

実行記録の保存は親が adapter の手順に従い、必要な承認をその操作について取得します。記録の保存だけが失敗したら成果物を保全し、記録だけをやり直します。回収が済んだら `hc rm` で自分の子を片付けます。ウィンドウに作業を表示する必要があれば `herdr-app` の手順を使います。
