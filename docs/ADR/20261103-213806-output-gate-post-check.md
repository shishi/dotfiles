# 最終回答を表示前に検査する

- 状態: 採用
- 日付: 2026-11-03

## 背景

指示をモデルに渡すだけでは、未確認の主張や依頼の抜けを表示前に検出できません。不可逆な操作には実行前のガードが必要です。

## 決定

最終回答を別のモデルで検査し、未達があれば同じセッションで作業を続けさせます。検査に失敗した場合は、確認が未完了であることと原文を表示します。危険な操作の実行前ガードは併用します。

検査には現在も有効な依頼・制約、回答、必要なツールの呼び出しと結果、応答規則を使います。会話と証拠の原文は別に保存し、識別子と版を指定して必要な範囲を取得します。各主張と依頼の充足に必要な証拠を対応付け、検査役が取得した原文で判定します。送信前に秘密情報を検出して伏せます。規則は、回答の訂正か作業の続行で解消できる違反を対象にします。

有効な依頼と原文の参照はセッションを通じて保持します。完了・取消・訂正を根拠に整理し、古さや話題の変更だけでは未完了の依頼を削除しません。入力上限と呼び出し予算は、情報の選択と判定の全体に適用します。連続する原文の反復は、回数と順序を保つ可逆表現で渡します。元の原文を再構成できることを確認し、同じ内容の展開による入力の消費を減らします。

## 選択肢

| 方式 | 判断 |
|---|---|
| 事前に指示するだけ | 表示前に未達を検出できません |
| 未達を添えて表示する | 未達を解消していない回答が届きます |
| 未達を返して続行する | 未達の解消を試みられます |
| 実行前ガードだけを使う | 操作は判定できますが、回答の内容は判定できません |
| 毎回すべての作業履歴を渡す | 履歴の増加で入力上限を超えます |
| 古い履歴から一律に削る | 有効な制約と必要な証拠を失います |
| 有効な依頼を保持し、必要な原文を取得する | 履歴全体の再送を避けながら根拠を確認できます |

## 影響

- 回答ごとに検査の時間とモデルの利用枠が必要です。
- 誤判定は不要な差し戻しを、見落としは未達の回答の表示を招きます。情報の選択も判定対象であり、有効な条件の保持と原文の再取得を検証します。
- 回答後の検査では、実行済みの操作を取り消せません。
- 対応する hook や中継を利用できない経路では、表示前の保留や続行を保証できません。
