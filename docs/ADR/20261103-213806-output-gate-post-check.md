# エージェントの最終回答を事後検査し、規則に反する回答は通るまで差し戻す

| | |
|---|---|
| **Status** | accepted |
| **Date** | 2026-11-03 |
| **Decision-makers** | リポジトリの所有者 |

## Context and Problem Statement

このリポジトリは、Claude Code と Codex に守らせる規則を、入力のたびに hook で文脈へ注入してきました (`agent-shared/hooks/wording-policy.sh`、`task-policy.sh`)。注入は規則をモデルに渡すだけで、守らなかった回答もそのまま利用者に表示されます。実際に、確かめていない結果を確かめたと書く回答、依頼の一部を落とした回答、失敗を和らげて書いた回答、口調や答え方の規則を外れた回答が表示されていました。

規則を守らせる仕組みを、モデルへの依頼から、表示の前の検査へ移す必要があります。検査の仕組み (出力ゲート) の構成と測定は [docs/output-gate.md](../output-gate.md) に書いています。この ADR は、検査で何を確かめ、違反をどう扱うかの判断を記録します。

## Decision Drivers

* 確かめられることを確かめずに出した回答、依頼の抜け、ごまかしを利用者に見せない
* 未達を報告する回答ではなく、未達を解消した回答だけを見せる
* Claude Code と Codex の両方で、CLI とデスクトップアプリの両方に同じ扱いを適用する
* 回答ごとの待ち時間を数秒に抑える
* 誤った判定で作業が止まり続けないこと

## Considered Options

1. 事前注入だけを続ける
2. 最終回答を検査し、未達を明記して表示する (差し戻しは 1 回まで)
3. 最終回答を検査し、未達が無くなるまで差し戻す
4. ツールの実行前に止める (PreToolUse の hook)

## Decision Outcome

**Chosen option**: "3. 最終回答を検査し、未達が無くなるまで差し戻す"。1 と 2 は、規則に反した回答がそのまま、または未達の一覧付きで利用者に届きます。3 だけが、検査を通った回答だけを見せるという要件を満たします。4 は回答の内容を判定できないため、3 の代わりにはならず、取り返しのつかない操作を止める補助として併用します。

### 判定の対象と種類

* 対象は各ターンの最終回答だけです。作業の途中で流れる発言は検査せず、最終回答の検査に「表示済みの文章」として渡します。途中の発言ごとに待たせないためです。
* 検査役は回答を書いたモデルとは別に起動します。入力は、最新の依頼、直近の会話、回答、ツールの呼び出しと結果 (証拠)、確かめる規則の一覧です。証拠の中の秘密情報は gitleaks で見つけて伏せてから送ります。
* 検査役は次の種類で未達を返します。
  * 確認していない主張: 確かめた・通ったと書いているのに、対応する呼び出しと結果が証拠に無い。背景の処理を起動した記録や、別の担当へ渡した記録は、その結果とはみなさない
  * 依頼の抜け: 依頼の項目に、回答も証拠も対応していない
  * ごまかし: 未解決の失敗や未確認を隠すか、根拠の無い安心表現で和らげている
  * 規則違反: `agent-shared/bin/output-gate-rules.json` の規則に反している
* 共通指示の「応答」の規則のうち、禁止語と謝罪・自己評価だけは、意味を変えない置き換えで直して表示します。差し戻すまでもないためです。口調などそのほかの規則は、規則違反として判定します。

### 差し戻し

* 未達があれば回答を表示せず、未達の一覧をエージェントへ返して、同じセッションで作業を続けさせます。直した回答も同じように検査し、未達が無くなるまで繰り返します。回数の上限は設けません。
* どの未達も、回答を書き直すことで解消できるようにします。エージェントは、主張を確かめるか、確かめられない主張を回答から外すか、起きたことを回答で報告すれば解消できます。規則一覧もこの前提で書くため、差し戻しは終わります。
* 次の場合は差し戻さずに表示します。
  * 検査役が動かない、または時間内に答えない場合: 検査しなかった理由を添えて原文を表示します。検査の故障で作業が止まり続けないためです。
  * 同じセッションで続けさせる手段が無い場合 (Codex で続行の登録が無いセッション、打ち切られた応答、Claude Code のデスクトップアプリの WSL セッションの 1 回目): 未達の一覧を付けて表示します。詳しくは [docs/output-gate.md](../output-gate.md) の「満たせない範囲」にあります。

### 規則一覧の書き方

`output-gate-rules.json` の各規則は `{id, text}` で、`text` は「対象」「違反」「違反にしない」の順に書きます。

* 検査役が見られるのは回答・会話・証拠だけなので、それだけで判定できる形にします。
* 違反は、回答を書き直せば解消できる形で書きます。過去の操作そのもの (push の実行など) を違反にすると、証拠から消せないため差し戻しが終わりません。そうした操作は「回答が報告していない」ことを違反にします。
* 既定の判定の種類と重なる規則は一覧に入れません。同じ違反が二重に指摘されるためです。
* 回答の本文にある秘密情報は、検査役が伏せた入力しか見られないため、検査処理が gitleaks で確かめて T9 の違反にします。回答が今のターンの証拠の秘密情報を書き写した場合も違反にします。検査役が検査しなかった場合は、この確認も行いません。
* 事前注入の規則のうち、利用者が選んだものを次のように割り当てています。

| 事前注入の規則 | 事後検査での扱い |
|---|---|
| 口調、依頼に直接答える、確認の問いには結論だけ、結論を先に、指摘には直した結果で応える、可否には条件を添える | 規則 W1・W2・W3・W4・W5・W9 |
| 未検証の安心表現を使わない | 既定の「ごまかし」 |
| 不明な事実を調べてから答える | 規則 T2 (確かめたと書いた主張は既定の「確認していない主張」) |
| 依頼の全項目に応える、未確認を隠さない | 既定の「依頼の抜け」「ごまかし」 |
| 利用者の条件を変えない | 規則 T1 |
| 結果を先に書き、経緯を並べない | 規則 W4 (結論を先に、と統合) |
| 作業を利用者に戻さない、利用者への依頼は最小にする | 規則 T7 (二つを統合) |
| 秘密情報・私的情報を出さない | 回答の秘密情報は検査処理の gitleaks、公開物の私的情報は規則 T9 |
| 完了は検証で判断する | 既定の「確認していない主張」 |
| 指示の無い push や破壊的な Git 操作をしない | 規則 T10 (実行した場合に回答が報告しているかを判定する) |
| 原因を直さない穴埋めを解決と呼ばない | 規則 T11 |
| 背景の作業の結果を確かめる | 既定の「確認していない主張」 |

入力のたびに規則を注入していた `wording-policy.sh` と `task-policy.sh` は、スクリプトごと止めています。各スクリプトの先頭に、止めている旨と戻し方を書いています。そのため、事後検査へ移していない規則 (委譲や背景の作業の締切、調査・レビュー・commit の手順など) も入力ごとの注入が無くなり、常に読み込まれる共通指示 (`AGENTS.md`) だけで守らせることになります。Nix の devShell を使う規則は、`flake.nix` のあるプロジェクトでだけ使う `nix-environment` skill へ移しました。

### Consequences

**Positive:**
* 検査役が規則違反と判定した回答は、同じセッションで続けさせられる経路では利用者に表示されません。
* 規則の本文を入力のたびに文脈へ入れなくなります。
* 規則を増やすには一覧に 1 件足すだけで、両方の CLI に同じ検査が適用されます。

**Negative:**
* 最終回答ごとに検査の時間が加わります。検査役を Claude の Opus / 推論量 low にした規則ごとの試験 32 件 (6 件ずつ並行して実行) では、1 件あたり平均 6.4 秒、最大 8.7 秒でした。差し戻すたびに、エージェントの作業時間と検査 1 回分が加わります。
* 検査役が誤って違反と判定すると、不要な差し戻しが起きます。見落とせば、違反した回答が表示されます。
* 回答を書いた後に検査するため、push のような取り返しのつかない操作は止められません。T10 は実行後に回答で報告させるだけです。実行前には、PreToolUse の hook (`agent-shared/hooks/command-judge.sh`) が、利用者の許可の無い push などの外部への操作を、Claude Code では利用者に確認し、Codex では止めます (判定役を動かせないときは警告して通します)。
* 続けさせる手段が無い経路では、未達の一覧付きで回答が表示されます。
* 事後検査へ移していない規則は、入力ごとの注入が無くなったぶん、守られにくくなるおそれがあります。
* 回答と証拠に表れない規則 (作業手順の守り方など) は判定できません。
* 検査役が動かないときは、そのターンの回答は検査されずに表示されます。

**Neutral:**
* 検査役のモデルは、見落としの無い候補のうち最も速いものを既定にしています (Claude の Opus / 推論量 low、代わりに Codex の gpt-6.1-terra / low)。選び方は [docs/output-gate.md](../output-gate.md) の「検査役のモデル」にあります。

### Confirmation

* `tests/output-gate-check.py` で、規則違反の指摘の組み立て、一覧に無い規則の指摘を捨てること、回答の秘密情報を規則違反にすることを確かめます。
* `tests/output-gate-rules-live.py` で、規則ごとに違反する回答と守る回答を本番と同じ検査役に通し、違反する回答でだけその規則の違反 (既定の種類へ任せた項目はその種類) が返ることを確かめます。検査役のモデルを実際に呼ぶ手動の試験で、規則の本文や検査役への指示を変えたときに実行します。
* 確認していない主張・依頼の抜け・ごまかしの見落としが増えていないことを、正解を決めた事例で確かめます。比べ方と基準は [docs/output-gate.md](../output-gate.md) の「検査役のモデル」に書いています。

## Pros and Cons of the Options

### 1. 事前注入だけを続ける

* Good, because 入力ごとの費用がスクリプトの起動と注入する文字数だけで済む
* Bad, because 守らなかった回答もそのまま表示される
* Bad, because 規則を増やすほど、入力のたびに文脈を消費する

### 2. 未達を明記して表示する (差し戻しは 1 回まで)

* Good, because 差し戻しが 1 回で終わり、待ち時間の上限が読める
* Bad, because 未達を解消していない回答が、未達の一覧付きで利用者に届く

### 3. 未達が無くなるまで差し戻す

* Good, because 検査を通った回答だけが表示される
* Good, because どの未達も回答の書き直しで解消できる形にしており、差し戻しが終わる
* Bad, because 誤った判定が続くと、そのぶん差し戻しが繰り返される
* Bad, because 回答の書き直しで解消できない規則を一覧に入れると、差し戻しが終わらなくなる

### 4. ツールの実行前に止める

* Good, because push などの取り返しのつかない操作を、実行される前に止められる
* Bad, because 回答の内容 (確認していない主張、依頼の抜け、口調など) は判定できない
